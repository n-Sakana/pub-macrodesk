# MacroStudio

**beta 1.0.0**

Excel マクロ（VBA）を、**VBE を一度も開かずに** 見て・調べて・直すためのツールです。

**マクロの改修が必要なのに、VBA に詳しい人が身近にいない。** そういう場面で、
チャット AI を相談相手として使い、マクロの中身の確認・診断・改修を
画面の案内だけで進められるようにします。

改修の判断はチャット AI（例: Microsoft 365 Copilot Chat）が行い、MacroStudio は
判断材料を運び、返ってきた結果を安全にブックへ書き戻す配管に徹します。

> **このツールは判断をしません。** どこを直すか・どう直すかの判断はすべてチャット AI が行い、
> このツールは「判断材料を運び、結果を安全にブックへ書き戻す」配管に徹します。
> そのため、依頼のひな形を差し替えれば、どんな目的にも使えます。
> 同梱の 5 つのひな形は、その一例にすぎません。

---

## 3 つの使いかた

読み込んだマクロに対して、次のどれかを選びます。ブックを書き換えるのは
「改修する」だけで、あとの 2 つは AI へ渡すファイルを作って終わります。

| 選ぶもの | すること | 作られるもの |
|---|---|---|
| **マクロを改修する** | AI に直してもらい、改修済みブックを作る | 改修済みブック・差分レポート・改修メモ |
| **マクロについてAIに聞く** | 動くかどうかの診断、進め方の相談、自由な質問 | AI へ渡す依頼文とコード全文 |

どちらの側にも、同梱のひな形・自分で足したひな形・自由に書けるひな形があります。

**元のブックは、どの使いかたでも変更しません。** 改修した結果は必ず別名の新しい
ブックとして、専用フォルダに作られます。

## 使い方

起動は **`launch.vbs` をダブルクリック**（黒い画面は出ません）。
画面右上の月／太陽ボタンでライトとダークを切り替えられ、選択は次回起動時も維持されます。

画面は 1 つずつ進みます。**右下の［次へ］が青くなったら次の画面へ**、
やり直したいときは隣の［戻る］です。

### ① ブックを読み込む
Excel ファイル（`.xlsm` など）を画面にドラッグ＆ドロップします
（クリックしてファイルを選ぶこともできます）。
次の画面でモジュール数と行数を確認し、その次で「改修する／AIに聞く」を選びます。

### ② AIへ依頼する
選んだ使いかたに応じて、依頼の内容を 1 つ選びます。選べるのは `presets\` フォルダの
Markdown（ひな形）で、一覧に出る名前はファイル名ではなく、ファイル内の見出し
（`# ...`）です。同梱しているのは次の 5 つです。

| 選択肢 | 使いかた | 何をするか |
|---|---|---|
| VBAリファクター（動きを変えずに整理・改善する） | 改修 | 動作を変えずに、読みやすさ・速さ・壊れにくさを直します |
| Win32 API を使わない形へ直す | 改修 | Win32 API に依存した箇所を、VBA 標準機能だけの形へ置き換えます |
| 自分で改修内容を書く | 改修 | 改修してほしい内容を自分の言葉で書きます |
| 新しい端末で動くか診断する | 診断 | 動かなくなる箇所と直し方の方針を挙げてもらいます |
| AIと相談して、改修の進め方を決める | 診断 | 質問に答え、AI と話しながら方針を決めます |
| 自分で聞きたいことを書く | 診断 | 聞きたいことを自分の言葉で書きます |

選ぶと、その**改修指示**が依頼文になり、同じファイルの**出力指示**（返答のしかた）も
一緒に付きます。

ひな形に**質問**が書かれているときは、次に質問が 1 問ずつ出ます。上の丸で何問目かが
分かり、左右の矢印で行き来できます。分かるところだけ答えれば大丈夫で、答えた内容は
依頼文へ折り込まれます。質問はひな形の書きかた次第なので、改修側のひな形でも使えます。

そのあとの画面の「依頼文を確認・編集」を開けば、送る前に文面を直せます。

［次へ］を押すと、**この改修専用のフォルダ**が作られ、`request.md`（依頼文）と
`source-code.md`（VBA コード全文）が書き出されます。
最後の画面で **［依頼文をコピー］** と **［ファイルの場所を開く］** を押し、
チャット AI に依頼文を貼り付け（Ctrl+V）、`source-code.md` を添付して送信します。
マクロが読み書きする Excel シートやファイルがあれば、それも一緒に添付すると
回答が正確になります。

依頼文の**組み立て枠**を変える場合は、`templates\request-template.txt` を UTF-8 で
編集します。依頼を作るたびに読み直されるため、ツールの再起動は不要です。
チャットへ渡す**改修指示と出力指示の中身は、選んだひな形の Markdown が持ちます**
（テンプレートやツール本体には持たせません）。
添付するコードファイルの形式はツール側で固定です。
使える差し込み変数は [仕様書 §6](docs/SPEC.md#6-依頼の受け渡し形式コードファイルとプロンプト) を参照してください。

#### ひな形（`presets\*.md`）の書き方

1 ファイルが 1 つの依頼の正本です。名前・改修指示・出力指示をその 1 枚に書きます。

```markdown
# ひな形の名前

<!-- この行のようなコメントは編集者向けです。チャットへは渡りません -->

## 改修指示

（このひな形の目的。ここが依頼文になります）

## 出力指示

（返答のしかた。1 つのコードブロックにまとめること、区切り行の書き方、
　変更は最小限に、無関係な行はそのまま、変更したモジュールと新しいモジュールは
　全文、チャット本文で返す、など）
```

- 最初の `# ...` が一覧に出る名前です（ファイル名は表示に使いません）。
- `## 改修指示` と `## 出力指示` の 2 つが必要です。見出し名はこのとおりに書きます。
- `## 用途` に `改修` / `診断` / `相談` と書くと、その使いかたの一覧に並びます
  （省略すると `改修` 扱いです）。
- `## 質問` を書くと、アプリが 1 問ずつ質問する画面が出ます。
  `- 質問文` で 1 問、その下に字下げして `- 選択肢` を並べると選択式になります。
  字下げが無ければ自由記述になります。
- `<!-- ... -->` のコメントは、チャットへ渡す依頼文から取り除かれます。
- 出力指示の中の `{{REQUEST_ID}}` は、依頼を作るたびに発行される**今回の依頼番号**へ
  置き換わります。取り込みの照合に使うので、消さないでください。
- 増やすときはファイルを複製して中身を書き換えるだけです。同じ出力指示を複数の
  ひな形に書いてかまいません（1 枚で完結させるのが目的です）。
- 書式が足りないファイルは選べず、目的の画面に「読み込めないひな形」として
  ファイル名と理由が出ます。直せばそのまま使えます。
- ファイルの追加・削除・名前変更・見出しの変更は、目的の画面を開き直せば反映されます。

### ③ 返答を取り込む
チャット AI は、変更したモジュールと新しく作ったモジュールの全文を
**1 つのコードブロック**にまとめて返します。そのコードブロックをコピーして、
**［クリップボードからAIの返答を取り込む］** を 1 回押すだけです（Ctrl+V でも可）。
モジュールを選ぶ必要も、1 つずつ貼る必要もありません。

コードブロックの中には、依頼番号入りの区切り行が入っています。ツールはこれを見て、
どのモジュールがどこまでかを判断し、**今回の依頼への返答かどうか**も確かめます。
別の依頼の返答、途中で切れた返答、同じモジュールが 2 回入った返答などは取り込まず、
どうすればよいかを 1 行で表示します（何も取り込まないので、やり直せます）。

取り込めると「3個のモジュールを取り込みました」と結果が出ます。AI が書いた
**改修内容の要約**も一緒に取り込まれるので、**「AIが書いた改修内容を見る」** を開けば
何をされたのかを日本語で読めます。

次の画面では、まず結果の要約が出ます。中身を見たいときは
**「変更内容を見る」** を開くと、左にモジュール一覧（標準・クラス・シートで区分）、
右に GitHub と同じ**インライン差分**（削除行は赤、追加行は緑、左に行番号 2 列）が
出ます。［変更箇所のみ］［折り返し］と前後の変更ボタンで確認できます。
誤って付いたコードフェンスなど軽微な写し間違いは、**［手動修正］** でその場で
直せます（［修正を反映］で差分を確認し直せます）。

取り込めた内容がそのまま書き戻す対象です。採用ボタンはありません。
「これは違う」と思ったら［戻る］で取り込みや依頼の画面まで戻り、
取り込み直すか、言い直してください。元のブックは何も変わりません。

なお、**新しく増やせるのは標準モジュールだけ**です（既存のクラスモジュールなどを
直すことはできます）。新しいクラスやフォームを含む返答は取り込みません。

**「AIに聞く」はここで終わりです。** 依頼文をコピーしてファイルを渡したら、
右下が［完了］になります。あとはチャットの回答を読んで判断してください。
以下の ③ ④ は「改修する」を選んだときの続きです。

### ④ ブックを作る
出力するファイル名を確認して［次へ］を押すと、採用した変更だけを書き戻した
**新しいブック**が作られます（元のファイルは一切変更されません）。
作成物はすべて **この改修専用のフォルダ** にまとまります。

```
<元のブックのフォルダ>\MacroStudio\<ブック名>_<日付_時刻>    request.md            AIへ渡した依頼文
    source-code.md        元マクロのコード全文
    <ブック名>_macrostudio.xlsm  改修済みブック
    diff-report.html      変更内容の確認レポート（全モジュールを収録）
    result.md             改修の概要メモ（何をどう直したか）
```

完了画面の **［出力フォルダをエクスプローラーで開く］** でそのフォルダを開けます。
右下は **［完了］** になり、押すと最初の画面へ戻って次のブックに移れます。
ビルド後、ツールが自動でコードを読み直して「意図どおり書き込まれたか」を検証します。
最後に Excel で開いてマクロの動作を確認してください。

## このツールがやらないこと

- 改修対象の検出・提案（判断はすべてチャット AI 側）
- チャット AI の返答の自動解釈（人が読んで、人が選んで貼ります）
- モジュールの削除・名前変更、標準モジュール以外の新規追加
- 元ファイルの上書き（出力は常に別ファイル）

## 動作要件

| 項目 | 要件 |
|---|---|
| OS | Windows 10 / 11 |
| PowerShell | Windows PowerShell 5.1（OS 標準） |
| WebView2 ランタイム | 必要（Windows 11 は標準搭載。無い場合は起動時に案内を表示） |
| .NET Framework | 4.7.2 以降（OS 標準） |
| Microsoft Excel | ツール自体には**不要**。改修後の動作確認時に使用 |
| ネットワーク | ツール自体は**完全ローカル動作**（AI との通信はブラウザのチャット AI 側で行う） |
| インストール | 不要。**フォルダをコピーするだけ**（dotnet SDK 等も不要） |

対応ファイル形式: `.xlsm` / `.xlam` / `.xlsb` / `.xls`。判定は拡張子ではなくファイルの
中身で行うため、拡張子が違っても中に VBA があれば読み込みます（詳細は docs/SPEC.md）。
Excel で開いたままのブックもそのまま添付できます。

## 配布方法

1. このフォルダ一式を、配布先端末の任意の場所にコピーします。
2. 使用者には「`launch.vbs` をダブルクリック」とだけ案内します。
3. ひな形を差し替える場合は、`presets\` フォルダに Markdown ファイル（UTF-8）を
   置くだけです。書き方は「② 改修依頼をつくる」の項を参照してください。
   ファイル 1 つにつき 1 件、依頼の画面に自動で現れます。
   ツール本体の変更は不要です。
4. チャットへ貼り付ける依頼文の組み立て枠を変える場合は、
   `templates\request-template.txt` を UTF-8 で編集します。このファイルが無い、
   読み込めない、UTF-8 でない、または差し込み変数が不正な場合、依頼の準備は
   エラーで止まります。内蔵文面への置き換えは行いません。

> **ZIP でダウンロードしても動作します。** 万一起動しない場合は、ZIP のプロパティで
> **［許可する］** にチェックを入れてから解凍してください（Mark of the Web の解除）。

## うまくいかないとき

### そのほか

- **起動しない / 白い画面のまま** … WebView2 ランタイム未導入の可能性があります。起動時のエラー案内に従ってください。
- **「マクロが見つかりません」** … 対象ブックにマクロ（VBA プロジェクト）が含まれていません。
- **ブックを添付できない** … 対象ブックを Excel で開いたままにしていないか確認してください。
- **依頼テンプレートを読み込めない** … `templates\request-template.txt` が存在し、
  UTF-8 で保存され、必要な差し込み変数（`{{REQUEST_TEXT}}`）を含んでいるか
  確認してください。
- **返答を取り込めない** … コードブロック全体（区切り行を含む）をコピーし直して
  ください。それでも取り込めない場合は、依頼文をコピーし直して AI へ送り直すと
  新しい依頼番号で作り直せます。
- **ひな形が一覧に出ない / 「読み込めないひな形」に出る** … その Markdown に
  `# 名前`、`## 改修指示`、`## 出力指示` が揃っているか、UTF-8 で保存されているかを
  確認してください。画面には理由が表示されます。
- **ビルドに失敗した** … 画面の指示に従ってください。元のファイルは変更されていないので、何度でもやり直せます。
- ログ: `%LOCALAPPDATA%\MacroStudio\logs\` に動作ログが残ります。問い合わせ時に添付してください。
  起動そのものに失敗した場合も、その理由がこのログに記録されます。

## 開発者向け

- 仕様書: [docs/SPEC.md](docs/SPEC.md)
- 開発ガイド（ビルド制約・テスト）: [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md)
- 技術構成: PowerShell 5.1 + Add-Type(C#) + WPF + WebView2（UI 実体は HTML/CSS/JS）。
  外部依存はリポジトリ同梱の WebView2 DLL と OS 標準コンポーネントのみ。
- WebView2 DLL: NuGet パッケージ `Microsoft.Web.WebView2`（SDK 1.0.3856.49）の再配布 DLL 4 本を
  `lib/` に同梱しています。
- VBA の抽出・書き戻し（OLE2 複合ドキュメントの読み書き、MS-OVBA 圧縮ストリームの
  展開・再圧縮）は **MacroStudio 自身の実装**として `src/` に持ちます。外部ライブラリへの
  実行時依存はありません。
- デバッグ起動: `launch.bat`（コンソール表示あり）。アプリ内 F12 で DevTools。
