# MacroDesk

Excel マクロ（VBA）の改修を、**VBE を一度も開かずに** GUI だけで完結させるためのツールです。

改修の判断は Microsoft 365 Copilot Chat を「外部の頭脳」として借り、
MacroDesk は判断材料を運び、結果を安全にブックへ書き戻す配管に徹します。

> **このツールは判断をしません。** どこを直すか・どう直すかの判断はすべて Copilot Chat が行い、
> このツールは「判断材料を運び、結果を安全にブックへ書き戻す」配管に徹します。
> そのため、改修マニュアル（プリセット）を差し替えれば、どんな目的の改修にも使えます。
> 同梱の `presets\サンプル_新端末移行.md` は、その一例にすぎません。

---

## 使い方（4ステップ）

起動は **`launch.vbs` をダブルクリック**（黒い画面は出ません）。

### ① ブックを添付する
改修したい Excel ファイル（`.xlsm` など）を画面にドラッグ＆ドロップします。
マクロのモジュール一覧が左側に表示されます。

### ② 改修依頼をつくる
改修してほしい内容を入力します。**プリセットボタン**（`presets\` フォルダに置いた
改修マニュアルから自動生成されます）を押すと、マニュアル本文が入力欄に流し込まれるので、
必要なら書き足してください。
**［依頼ファイルを作成］** を押すと、ソースコード込みの依頼テキストファイルが
対象ブックと同じフォルダに作られ、エクスプローラがそのファイルを選択した状態で開きます。
そのファイルを **Copilot Chat に添付**し、「添付ファイルの依頼に従ってください」と送信します。

依頼ファイル全体の構成や AI への指示を変える場合は、
`templates\request-template.txt` を UTF-8 で編集します。［依頼ファイルを作成］を
押すたびに読み直されるため、ツールの再起動は不要です。`presets\*.md` は依頼入力欄へ
改修マニュアルを追記するもの、テンプレートは生成ファイル全体を定めるものです。
使える差し込み変数は [仕様書 §6](docs/SPEC.md#6-依頼ファイルプロンプト形式) を参照してください。

### ③ Copilot の返答を取り込む
Copilot はモジュール単位で改修後のコード全文を返します。
返答冒頭の「改修サマリー」（どのモジュールをどう変えたかの箇条書き）を読み、
左のモジュール一覧から対象を選んで、**［Copilotの返答を貼り付ける］** を押します
（コードブロックのコピーボタンでコピーしてから。Ctrl+V でも貼れます）。
その瞬間、左＝現在のコード／右＝貼り付けたコード の**左右比較（diff）**が表示されます。
変更箇所が意図どおりか確認してください。直したモジュールの数だけ繰り返します。
返答に新しい標準モジュールがある場合は、一覧末尾の
**［新規モジュールとして取り込む］** から名前を入力してコードを取り込みます。
「これは違う」と思ったら ② に戻って依頼を言い直せます。

### ④ ビルドする
**［ビルド］** を押すと、貼り付けを確定したモジュールだけを書き戻した**新しいブック**が、
元のブックと同じフォルダに別名で作られます（元のファイルは一切変更されません）。
同じ日時名の **改修差分 HTML** も作られ、変更した全モジュールの改修前後を
1 ファイルで確認できます。［出力フォルダを開く］が選択するのは改修済みブックです。
ビルド後、ツールが自動でコードを読み直して「意図どおり書き込まれたか」を検証します。
最後に Excel で開いてマクロの動作を確認してください。

## このツールがやらないこと

- 改修対象の検出・提案（判断はすべて Copilot 側）
- Copilot の返答の自動解釈（人が読んで、人が選んで貼ります。貼り間違えれば diff が真っ赤になるので気づけます）
- モジュールの削除・名前変更、標準モジュール以外の新規追加
- 元ファイルの上書き（出力は常に別ファイル）

## 動作要件

| 項目 | 要件 |
|---|---|
| OS | Windows 10 / 11 |
| PowerShell | Windows PowerShell 5.1（OS 標準） |
| WebView2 ランタイム | 必要（Windows 11 は標準搭載。無い場合は起動時に案内を表示） |
| .NET Framework | 4.7.2 以降（OS 標準） |
| Microsoft Excel | ツール自体には**不要**。改修後の動作確認時に使用 |
| ネットワーク | ツール自体は**完全ローカル動作**（AI との通信はブラウザの Copilot Chat 側で行う） |
| インストール | 不要。**フォルダをコピーするだけ**（dotnet SDK 等も不要） |

対応ファイル形式: `.xlsm` / `.xlam`（`.xlsb` は対応予定・検証中。`.xls` は対象外。詳細は docs/SPEC.md）

## 配布方法

1. このフォルダ一式を、配布先端末の任意の場所にコピーします（例: `C:\Tools\macrodesk`）。
2. 使用者には「`launch.vbs` をダブルクリック」とだけ案内します。
3. 改修マニュアルを差し替える場合は、`presets\` フォルダにマニュアル本文の
   Markdown ファイル（UTF-8）を置くだけです。ファイル 1 つにつきボタンが 1 つ、
   ② の画面に自動で現れます。ツール本体の変更は不要です。
4. 依頼ファイル全体の構成や AI への指示を変える場合は、
   `templates\request-template.txt` を UTF-8 で編集します。このファイルが無い、
   読み込めない、UTF-8 でない、または差し込み変数が不正な場合、依頼ファイルの作成は
   エラーで止まります。内蔵文面への置き換えは行いません。

> **ZIP でダウンロードしても動作します。** 万一起動しない場合は、ZIP のプロパティで
> **［許可する］** にチェックを入れてから解凍してください（Mark of the Web の解除）。

## うまくいかないとき

### そのほか

- **起動しない / 白い画面のまま** … WebView2 ランタイム未導入の可能性があります。起動時のエラー案内に従ってください。
- **「マクロが見つかりません」** … 対象ブックにマクロ（VBA プロジェクト）が含まれていません。
- **ブックを添付できない** … 対象ブックを Excel で開いたままにしていないか確認してください。
- **依頼テンプレートを読み込めない** … `templates\request-template.txt` が存在し、
  UTF-8 で保存され、必要な差し込み変数を含んでいるか確認してください。
- **ビルドに失敗した** … 画面の指示（レクチャー欄）に従ってください。元のファイルは変更されていないので、何度でもやり直せます。
- ログ: `%LOCALAPPDATA%\MacroDesk\logs\` に動作ログが残ります。問い合わせ時に添付してください。
  起動そのものに失敗した場合も、その理由がこのログに記録されます。

## 開発者向け

- 仕様書: [docs/SPEC.md](docs/SPEC.md)
- 開発ガイド（ビルド制約・テスト）: [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md)
- 技術構成: PowerShell 5.1 + Add-Type(C#) + WPF + WebView2（UI 実体は HTML/CSS/JS）。
  外部依存はリポジトリ同梱の WebView2 DLL と OS 標準コンポーネントのみ。
- WebView2 DLL: NuGet パッケージ `Microsoft.Web.WebView2`（SDK 1.0.3856.49）の再配布 DLL 4 本を
  `lib/` に同梱しています。
- VBA の抽出・書き戻し（OLE2 複合ドキュメントの読み書き、MS-OVBA 圧縮ストリームの
  展開・再圧縮）は **MacroDesk 自身の実装**として `src/` に持ちます。外部ライブラリへの
  実行時依存はありません。
- デバッグ起動: `launch.bat`（コンソール表示あり）。アプリ内 F12 で DevTools。
