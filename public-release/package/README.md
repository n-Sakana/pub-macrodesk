# MacroStudio beta 1.0.0

MacroStudio は、Excel ブックに含まれる VBA を読み取り、チャット AI へ相談するための
ファイルを作り、AI から受け取った修正内容を別のブックへ書き戻す Windows
アプリです。VBE を開かずに、コードの確認、相談、差分確認、改修版ブックの作成を
進められます。

このアプリ自身は、どこをどう直すか判断しません。AI の返答は必ず利用者が確認し、
最終的な動作確認を Excel で行ってください。本バージョンはベータ版です。

## 必要な環境

- 64 ビット版 Windows 10 または Windows 11
- Windows PowerShell 5.1
- .NET Framework 4.7.2 以降
- Microsoft Edge WebView2 Runtime
- 出力先へ書き込める権限
- Microsoft Excel（改修後のブックを開き、動作確認するときに必要）
- 利用するチャット AI の環境（MacroStudio とは別に、ブラウザ等で利用）

MacroStudio の起動や VBA の読み書きに Excel、dotnet SDK、インストーラーは
必要ありません。WebView2 Runtime が無い場合は、起動時に案内が表示されます。

## ZIP を展開して起動する

1. ZIP をローカルの書き込み可能な場所へ保存します。
2. ダウンロードした ZIP が Windows によってブロックされている場合は、ZIP の
   ［プロパティ］で［許可する］または［ブロックの解除］を適用してから展開します。
3. ZIP の中身をすべて同じフォルダへ展開します。ZIP の中から直接起動しないでください。
4. 展開先の `launch.vbs` をダブルクリックします。

起動スクリプトはデジタル署名されていません。組織の AppLocker、WDAC、EDR、
PowerShell ポリシー等で実行が禁止される場合は、ポリシーを回避せず管理者へ
確認してください。

## 試してみるためのサンプル

`sample-book\sample_win32_sleep.xlsm` を同梱しています。手元のブックで試す前に、
これを読み込んで一通りの流れを確かめられます。

業務マクロを模したブックで、標準モジュールが 4 つ（492 行）あります。
Win32 API の `Sleep` を 19 箇所で直に呼んでいるので、「Win32 API を使わない形へ
直す」の目的を選ぶと何が起きるかが分かりやすくなっています。改修しても
このファイルは変更されず、別名の新しいブックが作られます。

## 「AIで改修する」

1. 対象のブックをドラッグ＆ドロップするか、画面から選びます。
2. 改修の目的を選び、AI へ渡す依頼文を確認します。
3. MacroStudio が、対象ブックと同じ場所に実行フォルダを作り、
   `request.md` と `source-code.md` を出力します。
4. 利用者自身が `request.md` の内容をチャット AI へ貼り付け、
   `source-code.md` を添付します。
5. AI の返答にあるコードブロック全体をコピーし、MacroStudio へ取り込みます。
6. 画面の差分を確認してから、改修済みブックを作ります。

返答が長い場合は「モジュール単位出力」を選べます。AI から 1 モジュールずつ受け取り、
全モジュールが揃うと 1 件の改修内容として確認できます。

## 「AIで相談する」

マクロが新しい端末で動くか調べたい場合や、改修方針を相談したい場合に使います。
`request.md` と `source-code.md` を作るところまでは同じですが、AI の返答を
MacroStudio へ取り込まず、ブックも作りません。回答を読んで利用者が次の対応を
判断します。

## プライバシーと安全性

- MacroStudio 本体には、ブック、VBA コード、AI の返答を外部へ自動送信する処理は
  ありません。画面も端末内の同梱ファイルから読み込まれます。
- AI への送信は、利用者が依頼文を貼り付け、`source-code.md` を添付したときだけ
  発生します。機密情報や個人情報を送れるか、所属組織の規則と利用する AI
  サービスの取扱条件を事前に確認してください。
- クリップボードは、依頼文をコピーするときと、利用者が AI の返答を取り込む
  操作をしたときに使用します。
- ログは `%LOCALAPPDATA%\MacroStudio\logs\` に保存されます。ログにはローカルの
  ファイルパス、モジュール名、エラー詳細が含まれる場合があります。VBA
  コード本文を記録する設計ではありませんが、ログを第三者へ渡す前に内容を
  確認してください。
- WebView2 のキャッシュと画面テーマの設定は
  `%LOCALAPPDATA%\MacroStudio\WebView2Cache\` に保存されます。
- MacroStudio は VBA を実行しません。AI が作ったコードの安全性や正しさを保証したり、
  サンドボックスで検証したりはしません。

## 作成されるファイル

対象ブックと同じフォルダに、次の実行フォルダが作られます。

```text
<元ブックのフォルダ>\MacroStudio\<ブック名>_<日時>\
```

用途に応じて、次のファイルが入ります。

- `request.md` — AI へ貼り付ける依頼文
- `source-code.md` — 読み取った VBA コード全文
- `<ブック名>-Modified-<日付><元の拡張子>` — 改修済みブック
- `<ブック名>-Diff-Report-<日付>.html` — 全モジュールの差分レポート
- `result.md` — AI が返した改修概要

元のブックは上書きしません。改修済みブックは別名で作成し、書き戻した VBA を
MacroStudio が読み直して一致を確認します。元ブックの VBA が読み込み後に変わった
場合は、古いコードを基にした返答を書き戻さないようビルドを停止します。

## 対応形式と既知の制約

ファイルの中身に VBA プロジェクトがあるかを見て処理します。対象形式は
`.xlsm`、`.xlam`、`.xlsb`、`.xls` です。

- `.xlsm` は抽出、書き戻し、Excel での再オープンとマクロ実行を確認済みです。
- `.xlam` は合成ファイルで経路を確認していますが、Excel が作成した実ファイルでの
  検証は未完了です。
- `.xlsb` は実ファイルでの検証が未完了です。
- パスワード保護された VBA プロジェクトは実ファイルでの検証が未完了です。
- 4096 バイトセクターを使う複合ファイルは読み取れる場合がありますが、
  改修版の作成には対応していません。
- 新しく追加できるのは標準モジュールだけです。モジュールの削除、名前変更、
  新しいクラス、UserForm、シートモジュールの追加には対応していません。
- UserForm の画面部品やレイアウト、既存モジュールの非表示 Attribute 行は
  編集しません。
- 署名付き VBA プロジェクトは、コードを書き換えると署名が無効になります。
- マクロの不具合検出、改修方針の決定、AI の回答内容の保証は行いません。

どの形式でも、作成したブックを Excel で開き、目的の操作、計算結果、保存、
外部ファイル連携等を利用者自身で確認してください。

## うまくいかないとき

- **起動しない、または白い画面のまま**  
  WebView2 Runtime の有無を確認し、最新のログを見てください。
- **Windows がスクリプトや DLL を止める**  
  ZIP を展開し直す前にブロックを解除します。組織管理端末では管理者へ確認してください。
- **ブックを読み込めない**  
  ファイルが存在し、読み取り権限があり、VBA プロジェクトを含むか確認してください。
  Excel で開いたままでも読み込めます。
- **依頼のひな形が表示されない**  
  `presets` フォルダの Markdown が UTF-8 で保存され、必要な見出しを持つか
  確認してください。
- **依頼文を作れない**  
  `templates\request-template.txt` が存在し、UTF-8 で保存されているか確認してください。
- **AI の返答を取り込めない**  
  今回の依頼に対するコードブロック全体を、区切り行を含めてコピーし直してください。
- **改修済みブックを作れない**  
  元ブックのフォルダへ書き込めること、空き容量、同名ファイルを別のアプリで
  開いていないことを確認してください。
