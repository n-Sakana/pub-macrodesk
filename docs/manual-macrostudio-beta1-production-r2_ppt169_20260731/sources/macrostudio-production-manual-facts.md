## 1. 製品の同定

- 正式名: **MacroStudio**（一語。旧名 MacroDesk は現行に存在しない）
- 版表記: **beta 1.0.0**（README 冒頭、index.html `<title>MacroStudio beta 1.0.0</title>`、
  トップバー brand-beta、ホスト version=beta 1.0.0（test-hostservices 実測））
- ブランドマーク: トップバー左に「MS」の角丸タイル + MacroStudio / beta 1.0.0
- 一言定義: Excel マクロ（VBA）を、VBE を一度も開かずに見て・調べて・直すためのツール。
  判断はチャット AI が行い、MacroStudio は判断材料を運び、返答を検証して安全に
  ブックへ書き戻す配管に徹する（SPEC §1.1–1.2）。
- 起動: `launch.vbs` をダブルクリック（インストール不要、フォルダコピーだけ）。
- 動作要件: Windows 10/11、Windows PowerShell 5.1、WebView2 ランタイム、
  .NET Framework 4.7.2 以降。ツール自体に Excel は不要（最終動作確認時に使用）。
  完全ローカル動作（ツール自体は通信しない。AI との通信はブラウザ等のチャット AI 側）。
- テーマ: ライト既定。トップバー右端の月/太陽ボタンで切替、`localStorage` に保存。
- トップバー右に［最初から］（全状態を捨てて最初の画面へ）。

## 2. 想定場面と読者

- 場面: マクロの改修が必要なのに、VBA に詳しい人が身近にいない。
  例: 新しい端末でマクロが動かない、作った人が異動していて中身が分からない。
- 主読者: VBA や Office ファイルの内部構造を知らない業務担当者。
  ファイル添付ができるチャット AI（例: Microsoft 365 Copilot Chat）は日常的に使える。
- 三者の役割分担（SPEC §1.2）:
  - **チャット AI**: どこを直すか・どう直すかの判断。コードを書く。
  - **人**: 作業と目的を選ぶ。依頼文とファイルを AI へ渡す。返答を選んで取り込む。
    差分を確認して進める。最後に Excel で動作確認する。
  - **MacroStudio**: コードの取り出しと運搬、返答の機械検証、別ファイルへの
    書き戻しと再読検証。**内容の解釈・提案・自動判定はしない。**

## 3. 二つの作業（画面 0 の選択肢）

最初の画面「作業を選んでください」の 2 択（実画面文言）:

| カード | 説明文（実画面） | 内部 mode |
|---|---|---|
| AIで改修する | AIの返答を取り込んで、改修済みのブックをこのアプリで作ります。 | refactor |
| AIで相談する | AIチャットへ渡す依頼文とコードを作ります。ブックは変更しません。 | diagnose |

- 案内文: 「これからすることを、ひとつ選んでください。」
- 進捗バー: 作業選択前は「1 作業とブックを選ぶ」のみ。改修=4 手順
  （作業とブックを選ぶ / AIへ依頼する / 返答を取り込む / ブックを作る）、
  相談=2 手順（作業とブックを選ぶ / AIへ渡す）。
- 相談は受け渡し画面（AIチャットへ質問します）が終点で、右下が［完了］になる。
  取り込み・ビルドは通らない。成果物は request.md と source-code.md の 2 つ。
- どちらの作業でも元のブックは変更しない。改修の成果物は必ず別名の新しいブック。

## 5. ブック読み込みと読み取り結果の 2 段階表示

- ドラッグ＆ドロップまたはクリックでファイル選択。Excel で開いたままのブックも
  添付できる（共有読み取り。元ファイルはロックも変更もしない）。
- 判定は拡張子ではなく中身。多経路読取（ZIP 正常経路 → ZIP 修復走査 →
  OLE2 直読 → 生バイト復元の計 6 経路）で、読めたモジュールは必ず保持。
- 読み取り結果は意味の違う 2 通りだけを表示（実装 describeReadResult）:

| 表示（実文言） | 意味 | 読者がすること |
|---|---|---|
| 「マクロのコードは全モジュール読み取れています。」+ 理由 1 行 + 「コードの読み取りには影響していません。」 | ブック内部の管理情報や置き場所が規格どおりでなかっただけ | 何もしない |
| 「一部をバイナリレベルで読み取れませんでした。」+ モジュール名 + 「〜のコードが途中までの可能性があります。改修前後のコードを確認してください。」 | 該当モジュールのコードが途中までの可能性 | 改修前後のコードを見比べる |

- どちらの場合も読み込みは成功で、先へ進める。
- 理由 1 行の変種: 「ブックの中のマクロ部分が通常の場所になかったため、別の経路から
  取り出しました。」/「◯◯ の位置情報がブックの記録と合わなかったため、コード本体を
  探して読み取りました。」/「ブック内部の管理情報に、規格どおりでない箇所がありました。」
- マクロが無いブックは E-ATTACH-03 のカード表示（このブックにはマクロが無い）。

## 6. 目的の選択（ひな形 = presets\*.md）

- 一覧は `presets\` フォルダの Markdown から作る。表示名はファイル名ではなく
  ファイル内の H1。カードの 1 行は `## 説明` そのもの。画面 3 に入るたび読み直す
  （追加・差し替えは再起動不要）。
- 同梱ひな形 6 つ（現物 H1・説明・用途。ファイル名は H1 と同一 + 番号接頭）:

| H1（カード名） | 説明（カードの 1 行） | 用途 | 質問 | モジュール単位出力 |
|---|---|---|---|---|
| VBAリファクター（動きを変えずに整理・改善する） | 今の動きを変えないまま、コードを読みやすく直してもらいます。 | 改修 | なし | あり |
| Win32 API を使わない形へ直す | Win32 API を使っている箇所を、新しい端末でも動く書き方へ置き換えてもらいます。 | 改修 | なし | あり |
| 自分で改修内容を書く | どう直してほしいかを、この後の画面で自分の言葉で書きます。 | 改修 | なし | あり |
| 新しい端末で動くかを調べてもらう | コードは直さず、新しい端末で困りそうな箇所を洗い出してもらいます。 | 診断 | なし | なし |
| 相談用の依頼文を作る（進め方を決めたいとき） | いくつかの質問に答えると、進め方を相談する依頼文ができます。 | 診断 | 6問 | なし |
| 聞きたいことを自分で書く | マクロについて聞きたいことを、この後の画面で自分の言葉で書きます。 | 診断 | なし | なし |

- 「AIで改修する」を選ぶと用途=改修の 3 つ、「AIで相談する」を選ぶと用途=診断の
  3 つが並ぶ。
- 目的を選んだ時点で今回の**依頼 ID**（UUID v4）が発行される。選び直すと新しい
  ID になり、前の返答は取り込めなくなる（取り込み済みも破棄）。
- 書式が不正なファイルは「読み込めないひな形」欄に理由付きで表示され、選べない。
- ひな形は 1 ファイル 1 依頼の正本（名前・説明・改修指示・出力指示を 1 枚に持つ）。
  ファイルを複製して書き換えるだけで増やせる。

## 7. 質問画面（`## 質問` のあるひな形のみ）

- 見出し「いくつか教えてください」。1 問ずつ表示。上部の丸番号（ビーズ）で
  位置と回答済みが分かり、左右矢印・丸クリックで移動。
- 選択式（選択肢ピル）と自由記述（複数行）の 2 形式。
- 「分かるところだけで大丈夫です。1 つ以上答えてください」（実文言）。
- 回答は依頼文に【質問への回答】として折り込まれる。
- 同梱では「相談用の依頼文を作る」だけが持つ（6 問。1 問目は困りごとの選択式）。

## 8. 依頼文の画面

- 見出し「AIへ送る依頼文を用意しました」。既定では依頼文は畳まれており、
  「依頼文を確認・編集」開閉（文字数表示付き）を開くと全文編集できる。
- 編集欄下の注記: 「この文章と、返答のしかたの指示、コード全文ファイルをAIへ渡します。」
- 依頼文の組み立て: `templates\request-template.txt`（中立な枠）に、ひな形の
  改修指示（+ 質問回答 + 使用者の書き足し）と出力指示を差し込む。
  テンプレートは生成のたびに読み直される（編集反映に再起動不要）。
- ［モジュール単位出力（コードが長い時用）］チェック: 選んだひな形が
  `## 出力指示（モジュール単位）` を持つときだけ表示（同梱では改修用 3 つ）。
  ふだんは不要。コードが長く AI の返答が途中で切れるときだけ使う。
  ON: 「AIは変更するモジュールを1回の返答に1つだけ出し、次を出してよいか聞いてきます。」

## 9. AIチャットへの受け渡し

- 見出し「AIチャットへ改修を依頼します」（相談時「AIチャットへ質問します」）。
- ［次へ］でこの画面に入った時点で**この改修専用の実行フォルダ**が作られ、
  `request.md`（依頼文）と `source-code.md`（コード全文）が書き出される。
- カード 1「依頼文をチャットへ貼り付ける」: ［依頼文をコピー］→「コピーしました」。
  クリップボードに入るのは依頼文だけ（コード本文は入らない）。
- カード 2「コード全文ファイルを添付する」: ［ファイルの場所を開く］→
  「フォルダを開きました」。source-code.md をチャットへ添付する。
- 両方押すまで［次へ］無効。
- 注記（実文言）: 「マクロが読み書きするExcelシートやファイルがあれば、それも一緒に
  AIチャットへ添付すると、より正確な回答が得られます。」
- source-code.md は常に全モジュール収録（選別 UI は無い）。UTF-8 BOM、CRLF、
  ASCII 見出し（MODULE INDEX、種別ごとの一覧、Total 行）。
  Attribute ヘッダは含めない（VBE でも見えない行のため）。
- 依頼は常に 1 通のプロンプト + 1 添付。分割送信は無い（分けるのは返答側だけ）。

## 10. 返答の取り込み

- AI は変更モジュールと新規モジュールの全文を**ちょうど 1 つのコードブロック**で返す
  （ひな形の出力指示が指定）。区切り行は依頼 ID 入り:
  `'@MACROSTUDIO <依頼ID> SUMMARY BEGIN/END`（要約）、
  `BEGIN/END <種類> <モジュール名>`、`COMPLETE <数>`。先頭 `'` なので VBA コメント。
- 操作は［クリップボードからAIの返答を取り込む］1 ボタン（Ctrl+V も同じ）。
  モジュールを選ぶ・1 つずつ貼る操作は無い。
- 3 ステップ案内（実画面）: 1 AIの返答のコードブロックをコピーする /
  2 下のボタンでまとめて取り込む / 3 次の画面で内容を確認する。
- 機械検証（1 つでも不合格なら**何も取り込まない**）: 依頼 ID 一致 / 区切り対応 /
  入れ子なし / COMPLETE 存在・数一致 / モジュール重複なし / 種類が既知 /
  名前が VBA 識別子 / 中身が空でない / SUMMARY の閉じ。
- 成功表示: 「5個のモジュールを取り込みました」+「既存 4個・新規 1個。内容は次の
  画面で確認できます。」+「AIが書いた改修内容を見る」開閉（AI の要約 = SUMMARY）。
- 失敗時は理由コードを画面に出さず、次にどうするかだけ 1 文（状態は変わらない。
  やり直せる）。
- ［取り込み直す］は取り込み済みでも常に表示。取り込み直しは**全置き換え**
  （前回だけの変更・新規は残らない）。
- 新しく増やせるのは標準モジュールだけ。既存モジュールは種類を問わず改修可。
  既存の種類はブック側が正本（返答の種類表記が違っても読み替え、警告を常時表示）。
- モジュール単位出力時: 「2 / 5個を受け取りました」+ 受け取り済み番号・名前一覧 +
  足りない番号の名指し。全部そろうまで［次へ］無効。［最初から取り込み直す］で
  空にして 00 から入れ直す。統合後は通常と同一の確認・ビルド工程。

## 11. 変更の確認（インライン diff）

- 見出し「取り込んだ変更を確認します」。要約: 「5個のモジュールへ変更を取り込みました
  （n個は変更なし）」+「問題は見つかりません。中身を見るときは下を開いてください。」
- 「変更内容を見る」開閉で、左=取り込んだモジュール一覧（標準/クラス/フォーム/
  シートの見出し区分、+N -M 行数）、右=GitHub と同じインライン diff
  （削除=赤、追加=緑、行番号 2 列、行内差分マーク、空白=·、タブ=→ 可視化、
  VBA シンタックスハイライト）。
- ツールバー（実画面）: 変更 N 行 / モジュール種別名 / ［↑ 前の変更］［↓ 次の変更］
  （k/n 表示、Alt+↑/↓） / ［変更箇所のみ］（200 行超のモジュールは既定 ON、
  畳み区間は「…n 行を表示」で展開） / ［折り返し］（既定 ON） / ［手動修正］。
- 手動修正: 左=現在のコード、右=編集欄。誤って付いたコードフェンス等の軽微な
  写し間違いをその場で直し、［修正を反映］で通常の貼り付けと同じ正規化・diff 再計算。
  ［編集をやめる］で破棄。編集中は［次へ］が止まる。
- 採用ボタンは無い。**取り込めた内容がそのまま書き戻し対象**。やめたいときは
  ［戻る］で取り込みへ戻る（元ブックは何も変わらない）。

## 12. ブックを作る

- 画面 9「作成する改修済みブックを確認します」: 集計カード
  （書き戻し / 変更なし / 新規追加 / 元ブック=保持）と出力ファイル名入力欄。
  「拡張子は .xlsm のままにします。」ファイル名のみ・区切り文字不可・元の拡張子固定。
- 既定名: `<ブック名>-Modified-<yyyyMMdd><元の拡張子>`
  （日付は**ブックを読み込んだ日**で固定。再ビルドでも同じ名前を置き換える）。
- 画面 10「改修済みブックをビルドしています」:
  「書き戻し後にブックを読み直して、モジュール名とコードを検証しています。」
  通常 1〜2 秒想定。120 秒を超えても失敗にせず「時間がかかっています。終わるまで
  このままお待ちください」（処理の正本はホストの応答）。
- 画面 11 成功「改修済みブックを作成しました」: 実行フォルダのパス +
  ［出力フォルダをエクスプローラーで開く］+ 作成ファイル一覧（チェック付き行）:
  AIへ渡した依頼文 request.md / 元マクロのコード全文 source-code.md /
  改修済みブック <名前> / 変更内容の確認レポート <名前> / 改修の概要メモ result.md。
  ［完了］で最初の画面へ。
- 失敗時「ビルドできませんでした」: 「出力は作成していません。元のブックは変更されて
  いません。」+ モジュール別の結果表 + ［もう一度ビルドする］。all-or-nothing
  （検証を通らない出力は必ず破棄。中途半端なブックを残さない）。

## 13. 実行フォルダと成果物（実測値で確認済み）

```
<元のブックのフォルダ>\MacroStudio\<ブック名（拡張子抜き）>_<yyyyMMdd_HHmmss>\
    request.md                                  … AIへ渡した依頼文
    source-code.md                              … 元マクロのコード全文（固定形式）
    <ブック名>-Modified-<yyyyMMdd>.xlsm          … 改修済みブック（名前は画面で変更可）
    <ブック名>-Diff-Report-<yyyyMMdd>.html       … 変更内容の確認レポート（全モジュール収録）
    result.md                                   … 改修の概要メモ
```

- 相談（診断）のときは request.md と source-code.md の 2 つだけ。
- 実行フォルダは依頼作成時点（画面 5→6）で確定。同じ実行の再ビルドは同じフォルダの
  自分の成果物だけを世代交換する（アプリが作っていない同名ファイルは触らず停止）。
- result.md の見出し構成（実装 createResultMarkdown）:
  `# <ブック名> 改修メモ` → 実行日時 / 依頼の目的 / 依頼番号 / 作成した改修済みブック /
  元のブック（変更していません） → `## 改修内容`（AI の要約。無ければ
  「（返答に要約は入っていませんでした）」）→ `## 変更したモジュール`
  （表: モジュール/種類/追加/削除）→ `## 変更しなかったモジュール` →
  `## このフォルダのファイル`。

## 14. Diff レポート HTML（実生成物で確認済み）

- タイトル: `<ブック名> 改修差分`。ヘッダにブック名・ビルド日時・変更モジュール n / m。
- アプリの確認画面と同じ実装を同梱した閲覧専用版。左=モジュール一覧（**全モジュール**
  収録。変更なしも並び、選ぶと全行文脈の diff）、右=インライン diff。
- 動く操作: ［↑ 前の変更］［↓ 次の変更］、［変更箇所のみ］、［折り返し］、
  明暗切替、モジュール切替、「…n 行を表示」展開。
- **2026-07-31 の現行実装**: 明暗切替はモジュールツールバー右端のアイコンボタン
  （`#report-theme-toggle`、月／太陽アイコン、文字ラベルなし。aria-label は
  「テーマを切り替える（現在: ライト／ダーク）」）。ヘッダ内の
  ［ダークにする］テキストボタンは廃止（diff-report.js の themeButton）。
- 既定: 全行表示・折り返しあり・ライト。200 行超のモジュールは最初から変更箇所のみ。
- 高さ制限なし（ページ全体が伸びる）。編集操作なし（textarea/input ゼロ）。
- 自己完結 1 ファイル。外部 CSS/JS/フォント/画像/通信なし。ブラウザで開くだけ。
  スクリプト無効時は noscript で理由を表示。

## 15. 安全の仕組み（実装で確認済み）と保証しない範囲

アプリが守るもの（受け渡しと構造の完全性）:

1. **元のブックを上書きしない。** どの作業でも元ファイルは変更しない。改修結果は
   常に別名の新しいブック（コピーに書き戻し）。ビルド失敗時は出力自体を残さない。
2. **コードを AI へ自動送信しない。** 通信機能が無い。渡すのは人がコピーする依頼文と、
   人が添付する source-code.md だけ。
3. **返答は機械検証してから取り込む。** 依頼 ID・区切り・終端・重複・種類・名前・
   件数を検査し、1 つでも不合格なら何も取り込まない（§10 の検証表）。
4. **ビルド前に元ブックの同一性を確認する。** 添付時点の VBA 内容署名と、ビルド直前に
   読み直した内容が完全一致しなければ E-BUILD-04 で中止（出力を作らない）。
   AI へ渡した後の手直しを黙って失う経路を閉じるため。
5. **書き戻し後に再読して検証する。** 出力ブックを読み直し、(a) 書き戻した全モジュールの
   コード一致 (b) それ以外の全ストリームの byte 単位一致 (c) 構造・名前・種別の維持を
   確認。1 つでも失敗したら出力を削除（all-or-nothing）。
6. VBA 以外（シートのデータ、書式、数式）には触れない。zip 内の vbaProject.bin 以外の
   エントリは変更しない。

保証しないもの（人の責任範囲）:

- **改修後のマクロが業務上正しく動くことは保証しない。** 検証が確かめるのは
  「取り込んだコードがそのまま入ったこと」と「それ以外を変えていないこと」まで。
  コードの中身の正しさは AI の返答次第であり、**最後の実務テストは人が行う**。
- AI の返答の品質・内容はツールの検証対象外（人が diff で確認して選ぶ）。

最終確認の最小セット（本マニュアルの推奨手順）:

1. 改修済みブックを Excel で開く（元のブックではなくフォルダ内の Modified 版）。
2. いつも使うマクロを、いつもの手順で 1 回実行する。
3. 結果（出力・集計・保存物）がいつもどおりかを確認する。
4. 問題があれば元のブックで業務を続け、依頼からやり直す（元のブックは無傷）。

## 16. 困ったときの戻り先（実装の状態遷移から）

| 起きたこと | 表示・状態 | 戻る先・すること |
|---|---|---|
| 返答を取り込めない | 1 文の案内。何も取り込まれない | コードブロック全体をコピーし直して再度取り込む |
| 別の依頼の返答だった | 取り込めない | いまの依頼文を送り直す（依頼を作り直したら返答も取り直し） |
| 取り込んだ内容が意図と違う | diff で分かる | ［戻る］で取り込みへ戻り、AI に言い直して新しい返答を取り込み直す |
| 写し間違い（余計なフェンス等） | diff が乱れる | ［手動修正］で直して［修正を反映］ |
| 「同じ番号のモジュールが、前と違う内容で届きました」 | 分割受け取りの重複 | ［最初から取り込み直す］で 00 から |
| 「元のブックのマクロが、読み込んだときから変わっています」 | E-BUILD-04。出力なし | ブックを読み込み直して依頼を作り直す |
| ビルド失敗 | 出力なし・元ブック無傷 | ［もう一度ビルドする］。再発したらログを添えて配布元へ |
| ビルドが長い | 「時間がかかっています」 | 待つ（処理は続いている） |
| 全部やり直したい | — | トップバー［最初から］ |

- 別ブックを読み込み直すと、選んだ作業以外の状態はリセット（取り込みがあれば確認
  ダイアログ）。
- ログ: `%LOCALAPPDATA%\MacroStudio\logs\macrostudio_<yyyyMMdd>.log`
  （コード本文は記録しない）。

## 18. 技術付録の事実（IT・管理者向け）

### 18.1 Excel を開かずに VBA を読む仕組み

- `.xlsm/.xlam/.xlsb` は ZIP コンテナで、VBA プロジェクト全体は `xl/vbaProject.bin`
  1 ファイルに入っている。`.xls` はファイル全体が OLE2。
- `vbaProject.bin` は OLE2（複合ドキュメント = CFB、[MS-CFB]）。中に dir・PROJECT・
  各モジュールのストリームがある。モジュールのソースは [MS-OVBA] §2.4.1 の圧縮。
- MacroStudio は自前実装（src/05_Ole2.cs / 06_VbaCompression.cs / 07_VbaProject.cs /
  08_BookIO.cs）で ZIP → OLE2 → 圧縮展開を辿ってソースを取り出す。実行時の外部
  ライブラリ依存なし（同梱 WebView2 DLL + OS 標準のみ）。
- 技術構成: PowerShell 5.1 + Add-Type(C#) + WPF + WebView2（UI は HTML/CSS/JS）。

### 18.2 受け渡しの照合（依頼 ID と返答パッケージ）

- 目的選択時に UUID v4 の依頼 ID を発行。依頼文の出力指示に区切り行として埋め込み、
  返答が書き写す。取り込みはこの ID の一致を最初に検査する（別依頼の返答の混入防止）。
- 返答パッケージの検証項目は §10 の表のとおり。検証は
  `assets/js/response-package.js` が唯一の実装。ツールは返答の意味を解釈しない
  （帳簿付けのみ: CRLF 正規化、コードフェンス除去、先頭 Attribute ブロック除去）。

### 18.3 書き戻しと検証

- ビルド手順: 添付時署名の一致確認（E-BUILD-04）→ 元ブックをコピー →
  vbaProject.bin を取り出し全ストリームをメモリ展開 → 変更モジュールのソース部だけ
  差し替え（PerformanceCache 部は温存。新規は標準モジュールとして dir/PROJECT/
  PROJECTwm へ追加）→ OLE2 を全面再構築 → コピー先へ書き戻し → 再読検証。
- 全面再構築が唯一の書き込み経路（in-place は 1 行の追加でも成立しないことを実測済み）。
- 検証: (a) 書き戻しモジュールのコード一致 (b) それ以外の全ストリーム byte 一致
  (c) 木構造・名前・種別・CLSID・state bits 維持。失敗は出力削除（all-or-nothing）。
- 品質ゲート: 無変更ラウンドトリップの byte 一致試験、読み直し検証、Excel 実機確認。

### 18.4 閲覧ロック・暗号化・署名（2026-07-30 実測含む）

- **VBA プロジェクトの閲覧ロック（パスワード保護）**: VBE の閲覧ゲートであり、
  モジュールストリーム自体は暗号化されない（MS-OVBA）。保護情報は PROJECT
  ストリームにあり、書き戻しで byte 単位に温存されるため、**ロックは維持され、
  元のパスワードで従来どおり解除できる見込み**。実ファイルでの確認は未実施
  （ベータ版の未確認事項。SPEC §15.2）。ロックの解除・回避機能は無い。
- **ファイル全体の暗号化（開くときにパスワードを求めるブック）**: 中身が
  EncryptedPackage（暗号化 OLE2）になり VBA コンテナに到達できない。実測
  （2026-07-30、Excel 16.0 で暗号化した複製）: モジュール 0 件で読み込まれ、
  先へ進めない。**扱えない**ので、パスワードを外した複製で作業する。
  ※実測時の表示は「マクロのコードは全モジュール読み取れています。」で、
  暗号化を名指ししない（製品側改善候補として別途報告）。
- **VBA 署名**: 署名は vbaProject.bin の外の別パート（xl/vbaProjectSignature.bin 等）
  にあり、モジュールを書き換えた時点でどの方式でも無効になる。MacroStudio は
  署名パートに触れない（再署名は組織の手順で）。署名済みブックでの実測は未実施。

### 18.5 対応形式と検証状態

| 形式 | 読み取り | 書き戻し | 検証状態 |
|---|---|---|---|
| .xlsm | 対応 | 対応 | 実機確認済み（抽出・書き戻し・Excel 再オープン・マクロ実行） |
| .xlam | 対応 | 対応 | 合成データ試験のみ（Excel 実生成ファイル未検証） |
| .xlsb | 対応（同一経路） | 対応 | 実ファイル未検証（失敗時は明示エラー） |
| .xls | 読み取り対応 | 検証合格時のみ | 限定対応 |
| 拡張子が違う | 中身で判定 | — | zip/OLE2 として読める場合は読む |

- その他の未検証・限定事項（SPEC §15.2 全 12 項の要点）: パスワード保護 VBA
  プロジェクトの実ファイル / v4(4096B) CFB は読みのみ・書き出しは v3 /
  120 秒超ビルドの実測 / モジュール単位出力を実チャット AI がどこまで守るか /
  他ブラウザエンジンでのレポート表示 / 日またぎ作業の出力名日付、など。

### 18.6 EDR / DLP 環境（同梱検証サンプル・2026-07-30 記録）

- 同梱: `samples/edr-dlp-validation/`（FIRST-OPEN runner + 分離した標本 +
  手順書 README.md / 記録 VALIDATION.md / SHA256SUMS.txt）。
  Excel/VBA の正規操作が EDR/DLP に検知・遮断される地点を、操作経路と標本形態ごとに
  観測する診断器。検知回避は目的にしない。
- 実運用 1 環境（本番管理端末）の正本結果:
  - 通過: 通常マクロ標本のバイナリ読み取り(A1)・複製(B1)、VBProject 書込み(D1)、
    クリップボードへのコピー(E1/E2)
  - 遮断: **Win32 API 宣言入り標本**の読み取り(A2)・複製(B2)・VBProject 書込み(D2)、
    クリップボード貼付+新規ブック保存(F1/F2)
  - 判定不能: C2（ログ残らず） / 未報告: C1
- ローカル開発機（EDR 制約なし・Excel 16.0）: 追加診断 X01〜X30 / Y01〜Y06 全 35
  ケース PASS（存在確認→開閉→1byte→4KiB→全読→再構築→貼付→保存の段階別）。
- 含意: **結果は環境依存**。ローカルの成功は本番 EDR の通過を意味しない。導入時は
  同梱サンプルを対象環境で一件ずつ実行し、停止地点と管理コンソールのイベントを
  照合する。未検証: 本番環境での X/Y、32-bit Excel、署名済みプロジェクト等。

### 18.7 運用メモ

- 配布: フォルダ一式のコピーだけ。ZIP 経由は Mark of the Web の解除が必要な場合あり。
- ひな形の差し替え・追加: `presets\*.md` を置くだけ（再起動不要）。
