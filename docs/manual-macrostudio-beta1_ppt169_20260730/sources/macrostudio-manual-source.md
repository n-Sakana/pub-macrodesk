# MacroStudio beta 1.0.0 操作マニュアル 原稿

この文書は PowerPoint 操作マニュアルの内容原本です。画面の見出し・ボタン名・案内文は
すべて 2026-07-30 時点の実装（`C:\repos\pub\macrostudio`）から抽出した実物であり、
推測で書いた文言はありません。添付のスクリーンショットも同じ版のアプリから取得しました。

対象読者: VBA や開発に詳しくない業務担当者。マクロを自分では書けないが、担当している
マクロを直す必要がある人。

---

## 1. このツールは何か

**マクロの改修が必要なのに、VBA に詳しい人が身近にいない。** MacroStudio はその場面の
ためのツールです。Excel マクロ（VBA）の中身を、**VBE（開発画面）を一度も開かずに**
確認・診断・改修できます。

判断はチャット AI（例: Microsoft 365 Copilot Chat）が行います。MacroStudio は
「AI に渡す材料を作る」「AI の返答を検証して安全にブックへ書き戻す」という配管に徹します。

覚えてほしい原則は 3 つだけです。

1. **元のブックは絶対に変更しません。** 改修結果は必ず別名の新しいブックとして、
   専用フォルダに作られます。
2. **画面は 1 つずつ進みます。** 右下の［次へ］が青くなったら次へ。やり直しは隣の［戻る］。
3. **迷ったら戻れます。** 取り込んだ内容も、依頼文も、往復しても保持されます。

---

## 2. 起動と画面の見かた

- 起動は `launch.vbs` をダブルクリック。黒いコマンド画面は出ません。
- 起動直後に小さな読み込み画面（MS マーク・MacroStudio・beta 1.0.0）が出て、
  準備ができると本画面に切り替わります。
- 画面右上の月／太陽ボタンでライト・ダークを切り替えられます。選択は次回も維持されます。
- 画面上部の帯が進捗です。**最初は「ブックを読み込む」だけが表示され**、目的を選ぶと
  その先の手順が現れます。改修を選べば 4 手順、AI に聞くだけなら 2 手順になります。
- 画面左下には「いま何をすればよいか」が 1 行で出ます。

---

## 3. 全体の流れ

読み込んだマクロに対して、まず **2 つのうちどちらか**を選びます。
ブックを書き換えるのは「改修する」だけです。

| 選ぶもの | すること | 終わったときにできるもの |
|---|---|---|
| マクロを改修する | AI の返答を取り込み、改修済みブックを作る | 改修済みブック・差分レポート・改修メモなど 5 ファイル |
| マクロについて AI に聞く | 診断・相談・自由な質問のための依頼文を作る | AI へ渡す依頼文とコード全文の 2 ファイル |

改修の流れ（画面 12 枚）:

| 手順 | 画面 | すること |
|---|---|---|
| 1・1/3 | Excelブックを読み込みます | 対象のブックを選ぶ |
| 1・2/3 | 読み込んだマクロを確認します | 読み取り結果を確認する |
| 1・3/3 | このマクロをどうしたいか選びます | 改修 / AI に聞く を選ぶ |
| 2・1/3 | どんな改修をするか選びます | 依頼の内容（ひな形）を選ぶ |
| 2・2/3 | AIへ送る依頼文を用意しました | 依頼文を確認する（必要なら直す） |
| 2・3/3 | AIチャットへ改修を依頼します | 依頼文をコピーし、ファイルを渡す |
| 3・1/2 | AIの返答をまとめて取り込みます | 返答を 1 回で取り込む |
| 3・2/2 | 取り込んだ変更を確認します | 変更内容を確認する |
| 4・1/3 | 作成する改修済みブックを確認します | 出力ファイル名を確認する |
| 4・2/3 | 改修済みブックをビルドしています | （自動） |
| 4・3/3 | 改修済みブックを作成しました | 出力フォルダを開く／完了 |

AI に聞くだけの流れは、手順 2・3/3「AIチャットへ質問します」で終わりです。
そこに［完了］が出ます。

## 4. 手順 1: ブックを読み込む

### 画面 1-1「Excelブックを読み込みます」

- 画面中央へ Excel ファイルをドラッグ＆ドロップします。クリックして選ぶこともできます。
- 対応形式は `.xlsm` / `.xlam` / `.xlsb` / `.xls`。画面右上にも表示されています。
- 案内文: 「改修したいブックを、ここへドラッグするか選んでください。」
- 読み込めると、ファイル名とパスが表示され、右下の［次へ］が青くなります。
- 選び直したいときは［選び直す］。

**よくあるつまずき**: マクロを含まないブックを選ぶと「このブックにはマクロが無い」旨の
カードが出ます。ファイルを間違えていないか確認してください。

### 画面 1-2「読み込んだマクロを確認します」

- 「受注管理.xlsm から 4モジュール・412行を読み込みました」のように結果が出ます。
- 中身を見たいときは **「読み取った内容を見る」** を開くと、モジュール名と行数の一覧が出ます。
- ここでは元のブックには一切書き込んでいません。

### 画面 1-3「このマクロをどうしたいか選びます」

2 枚のカードから 1 つ選びます。**選んでも自動では進みません。**［次へ］で確定します。

| カード | 説明文 |
|---|---|
| マクロを改修する | AIの返答を取り込んで、改修済みのブックをこのアプリで作ります。 |
| マクロについてAIに聞く | AIチャットへ渡す依頼文とコードを作ります。ブックは変更しません。 |

選ぶと、画面上部の進捗にその先の手順が現れます。

---

## 5. 手順 2: AI へ依頼する

### 画面 2-1「どんな改修をするか選びます」（AI に聞く場合は「AIに何を聞くか選びます」）

`presets` フォルダの Markdown（ひな形）が並びます。**一覧に出る名前はファイル名ではなく、
ファイル内の見出し（`# ...`）**です。同梱しているのは次の 6 つです。

| 選択肢 | 使いかた | 何をするか |
|---|---|---|
| VBAリファクター（動きを変えずに整理・改善する） | 改修 | 動作を変えずに、読みやすさ・速さ・壊れにくさを直します |
| Win32 API を使わない形へ直す | 改修 | Win32 API に依存した箇所を、VBA 標準機能だけの形へ置き換えます |
| 自分で改修内容を書く | 改修 | 改修してほしい内容を自分の言葉で書きます |
| 新しい端末で動くかを調べてもらう | AI に聞く | 動かなくなる箇所と直し方の方針を挙げてもらいます |
| 相談用の依頼文を作る（進め方を決めたいとき） | AI に聞く | 質問に答え、AI と方針を決めるための 1 通目を作ります |
| 聞きたいことを自分で書く | AI に聞く | 聞きたいことを自分の言葉で書きます |

ひな形は利用者が増やせます（後述）。

### 画面 2-2「いくつか教えてください」（ひな形に質問がある場合だけ）

- 質問が **1 問ずつ** 出ます。上の丸（番号入り）が進捗で、答えた問は色が付きます。
- 移動は左右の矢印、または丸を直接クリック。問数が多いときは中間の丸が省略されます。
- 選択式の問はボタンを 1 回押すだけ。自由記述の問は複数行で書けます。
- 分かるところだけで大丈夫です。1 問以上答えると［次へ］が使えます。
- 答えた内容は、次の画面の依頼文に【質問への回答】として折り込まれます。

### 画面 2-3「AIへ送る依頼文を用意しました」

- 依頼文はできあがっています。**そのまま進んで構いません。**
- 直したいときだけ **「依頼文を確認・編集」** を開きます。全文が編集できます。
- 依頼文には、この依頼だけの **依頼番号**（毎回変わる長い英数字）が埋め込まれます。
  これは返答を取り込むときの照合に使うので、消さないでください。

### 画面 2-4「AIチャットへ改修を依頼します」

［次へ］を押した時点で、**この改修専用のフォルダ**が作られ、2 つのファイルが書き出されます。

1. ［依頼文をコピー］を押す → クリップボードに依頼文が入ります
2. ［ファイルの場所を開く］を押す → エクスプローラーでフォルダが開きます
3. チャット AI に依頼文を貼り付け（Ctrl+V）、`source-code.md` を添付して送信します

**両方のボタンを押すまで［次へ］は使えません。**

画面には次の案内も出ます。

> マクロが読み書きするExcelシートやファイルがあれば、それも一緒にAIチャットへ添付すると、
> より正確な回答が得られます。

作られるファイルの場所は「作成されるファイルの場所を見る」で確認できます。

**AI に聞くだけの場合はここで終わりです。** 右下が［完了］になります。

## 6. 手順 3: 返答を取り込む（改修のみ）

### 画面 3-1「AIの返答をまとめて取り込みます」

- AI は、変更したモジュールと新しく作ったモジュールの全文を **1 つのコードブロック**に
  まとめて返します。
- そのコードブロックをコピーして、**［クリップボードからAIの返答を取り込む］を 1 回押すだけ**。
  Ctrl+V でも同じです。
- **モジュールを選ぶ必要も、1 つずつ貼る必要もありません。**
- 取り込めると「2個のモジュールを取り込みました」と結果が出て、既存・新規の内訳も出ます。
- AI が書いた改修内容の要約も一緒に取り込まれます。
  **「AIが書いた改修内容を見る」** を開くと日本語で読めます。

**取り込めないとき**（何も取り込まれないので、そのままやり直せます）

| 表示されること | 意味 | どうするか |
|---|---|---|
| 別の依頼への返答のようです | 依頼番号が今回のものと違う | 依頼文をコピーし直して AI へ送り直す |
| 返答が途中で切れているようです | 終わりの行が無い | コードブロック全体をコピーし直す |
| 取り込める形のコードが見つかりませんでした | 区切り行が無い | コードブロック全体（区切り行を含む）をコピーし直す |
| 同じモジュールが2回入っていました | 重複 | AI へ、モジュールごとに 1 つだけ返すよう伝える |
| クリップボードが空でした | コピーできていない | コードブロックのコピーボタンで取り直す |

### 画面 3-2「取り込んだ変更を確認します」

- まず結果の要約が出ます。**取り込めた内容が、そのまま書き戻す対象**です。
  採用ボタンはありません。
- 中身を見たいときは **「変更内容を見る」** を開きます。
  - 左: モジュール一覧。標準 / クラス / シートで区分され、`+5 −2` のように増減行数が出ます。
  - 右: GitHub と同じ **インライン差分**。削除行は赤、追加行は緑、左に行番号が 2 列。
  - ［変更箇所のみ］［折り返し］［↑前の変更］［↓次の変更］で確認できます。
- コードフェンスの写し間違いなど軽微な修正は **［手動修正］** でその場で直せます。
- 「これは違う」と思ったら［戻る］で取り込みの画面へ戻り、取り込み直せます。
  元のブックは何も変わりません。

## 7. 手順 4: ブックを作る（改修のみ）

### 画面 4-1「作成する改修済みブックを確認します」

- 出力ファイル名を確認します。既定は `<ブック名>_macrostudio.xlsm`。
- 名前はファイル名だけを入れます。`\` `/` などの区切り文字や、元と違う拡張子は使えません。
- 作成されるファイルの一覧は「作成されるファイルの場所を見る」で確認できます。

### 画面 4-2「改修済みブックをビルドしています」

- 自動で進みます（通常 1〜2 秒）。書き戻したあとブックを読み直して、
  意図どおり書き込まれたかを検証しています。

### 画面 4-3「改修済みブックを作成しました」

作成物はすべて **この改修専用のフォルダ** にまとまります。

```
<元のブックのフォルダ>\MacroStudio\<ブック名>_<日付_時刻>\
    request.md                    AIへ渡した依頼文
    source-code.md                元マクロのコード全文
    <ブック名>_macrostudio.xlsm    改修済みブック
    diff-report.html              変更内容の確認レポート（全モジュール）
    result.md                     改修の概要メモ（何をどう直したか）
```

- ［出力フォルダをエクスプローラーで開く］でそのフォルダを開けます。
- 右下は **［完了］**。押すと最初の画面へ戻り、次のブックに移れます。
- 最後に Excel で開いて、マクロの動作を確認してください。

## 8. 覚えておくとよいこと

### 新しく増やせるのは標準モジュールだけ

既存のクラスモジュールやシートのモジュールを**直す**ことはできます。
新しいクラスやユーザーフォームを含む返答は取り込みません。

### ひな形は自分で増やせる

`presets` フォルダに Markdown ファイル（UTF-8）を置くと、ファイル 1 つにつき 1 件、
目的の画面に自動で現れます。アプリの再起動は不要です。

```markdown
# ひな形の名前

<!-- この行のようなコメントは編集者向けです。チャットへは渡りません -->

## 用途

改修

## 改修指示

（このひな形の目的。ここが依頼文になります）

## 出力指示

（返答のしかた）
```

- 最初の `# ...` が一覧に出る名前です。
- `## 用途` に `改修` か `診断` と書くと、その使いかたの一覧に並びます（省略すると改修）。
- `## 質問` を書くと、1 問ずつ質問する画面が出ます。
- 書式が足りないファイルは選べず、理由付きで一覧の下に出ます。

### 差分レポート（diff-report.html）

ブラウザで開ける自己完結のファイルです。左にモジュールツリー、右にインライン差分。
**変更しなかったモジュールも含めて全モジュール**が入っているので、
改修後のブックの記録としてそのまま保管できます。

## 9. うまくいかないとき

| 症状 | 対処 |
|---|---|
| 起動しない・白い画面のまま | WebView2 ランタイムが未導入の可能性。起動時のエラー案内に従う |
| 返答を取り込めない | コードブロック全体（区切り行を含む）をコピーし直す。それでも駄目なら依頼文をコピーし直して送り直す |
| ひな形が一覧に出ない | その Markdown の見出しが揃っているか確認する。画面に理由が出る |
| ビルドに失敗した | 画面の指示に従う。元のファイルは変更されていないので何度でもやり直せる |

# 第一部（サービス説明）用の素材

この資料は「サービス説明」と「操作マニュアル」を兼ねます。前半で何ができる道具なのかを
伝え、後半で操作を案内します。専門用語や開発ツールの固有名詞は出さず、
「開発画面」「コード」といった普通の言葉で言い換えます。

第一部は仕組みの説明ではありません。「まとめて取り込む」「番号で取り違えない」のような
作り手側の理屈は書かず、読み手にとって何がどう変わるか（何ができるようになり、
何を心配しなくてよくなるか）で書きます。仕組みが必要な場面は第二部で扱います。

## A. 何が問題だったか

- 業務マクロは部門ごとに育ち、作った人はもう居ないことが多い。
- 直すには開発画面を開いてコードを読む必要があり、担当者には手が出ない。
- 端末やファイルの置き場所が変わると動かなくなるが、直せる人が身近にいない。
- 詳しい人に頼むと順番待ちになり、業務が止まる。

## B. このツールでできること

- **コードを読み書きできなくても、マクロを直せる。** 直しかたを考えるのは AI。
  こちらは画面に出てくることに答えるだけ。
- **開発画面を一度も開かない。** 案内どおりに［次へ］を押していけば終わる。
- **元のブックはそのまま残る。** 直したものは別名の新しいブックとして作られる。
- **鵜呑みにしなくていい。** どこが変わったのかを見てから、作るかどうかを決められる。
- **直さずに、聞くだけでもいい。** 「新しい端末で動くか」「どう直すのが良いか」を
  AI に相談するところで終わってもよい。

## C. 心配しなくてよくなること（読み手の側から見た特徴）

| 今までの心配 | このツールでは |
|---|---|
| 何をどう頼めばいいか分からない | 頼みたいことを選べば、AI へ渡す文章はこちらで用意される |
| コピペを間違えそう | 貼り付けは 1 回だけ。中身を仕分けて写す作業はない |
| 直った内容が正しいか分からない | 変わった場所を見てから、作るかどうかを決められる |
| 元のブックを壊しそう | 元のファイルには触れない。作り直せば何度でもやり直せる |
| 後で誰も説明できない | 何を頼み、何が変わったのかが 1 か所に残る |
| 部門ごとにやり方が違う | よく頼む内容は、自分たちのひな形として増やせる |

## D. 想定する使い方（ユースケース）

1. **端末の入れ替えに備える** — 新しい環境で動かなくなる箇所を洗い出してもらう（診断）。
2. **動かなくなったマクロを直す** — 使えなくなった機能を、標準機能だけの形へ置き換える（改修）。
3. **担当者しか触れないマクロを整理する** — 動きを変えずに読みやすく直す（改修）。
4. **どう直すか決める** — いくつかの質問に答えて、進め方を AI と相談する材料を作る（相談）。
5. **中身を知りたい** — このマクロが何をしているのかを聞く（質問）。

## E. 使う前に必要なもの

- Windows の PC と Excel。
- 使える AI チャット（Microsoft 365 Copilot Chat など、社内で許可されているもの）。
- 直したいマクロ入りのブック。
- 特別な権限やインストール作業は不要。`launch.vbs` をダブルクリックするだけ。

## F. このツールがやらないこと

- どこをどう直すかを決めること。それは AI に聞く。
- 元のブックを書き換えること。必ず別名で作る。
- マクロを勝手に増やして構造を変えること。増やせる範囲は限ってある（詳しくは第二部）。
- 直ったマクロを実際に動かして確かめること。最後に Excel で開いて確認するのは人。

## G. 位置づけ

- 現在はベータ版 1.0.0。画面の文言や配置は今後変わることがある。

## 10. このマニュアルの但し書き

- 画面は MacroStudio **beta 1.0.0** のものです。ベータ版のため、画面の文言や配置は
  今後変わることがあります。
- 掲載しているスクリーンショットは、サンプルのブック（受注管理.xlsm）を読み込んだ
  実画面です。フォルダのパスや日時は説明用の例です。
