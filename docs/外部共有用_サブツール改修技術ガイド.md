# Excel / Access サブツール改修ガイド（外部共有用・技術版）

## 1. 目的と適用範囲

本書は、Excel VBA、Access、Power Query、バーコード出力を含むサブツールを、新しいクライアント環境や保存先へ移行する際の技術的な確認事項、改修項目、テスト観点を整理したものです。

### 対象

- Excel マクロ有効ブック（`.xlsm`、`.xlam` など）
- Access データベース（`.accdb`、`.mdb` など）
- VBA から外部ファイル、フォルダー、データベースを参照するツール
- Win32 API、Windows Shell、ActiveX を利用するツール
- Power Query で外部データを取得するブック
- 特定フォントや ActiveX コントロールでバーコードを生成するツール

### 対象外

- 業務要件、運用組織、問い合わせ体制の設計
- 移行日程、担当割当、環境固有の申請手順
- 個別環境のサーバー名、URL、共有フォルダー名、認証情報

## 3. 改修対象の分類と判定

### 3.1 パス、ファイル、フォルダー操作

#### 主な検索対象

- UNC パスを示す `\\`
- ドライブパスを示す `C:\` 等
- `Dir`、`FileCopy`、`Kill`、`Name`、`MkDir`、`RmDir`
- `SaveAs`、`SaveCopyAs`
- `ChDir`、`ChDrive`、`CurDir`
- `ThisWorkbook.Path`、`ThisWorkbook.FullName`
- `ActiveWorkbook.Path`、`ActiveWorkbook.FullName`
- `Workbooks(...).Path`、`Workbooks(...).FullName`
- `GetAttr`、`SetAttr`、`FileLen`、`FileDateTime`
- `Open ... For Input/Output`、`Input#`、`Line Input#`、`Write#`、`Print#`、`EOF`、`LOF`

#### FileSystemObject の主な検索対象

- `FileSystemObject`
- `GetFile`、`GetFolder`、`FileExists`
- `CreateTextFile`、`OpenTextFile`
- `DeleteFile`、`CopyFile`、`MoveFile`
- `GetAbsolutePathName`、`GetParentFolderName`
- `GetFileName`、`GetExtensionName`、`GetBaseName`、`BuildPath`

#### 留意点

SharePoint 等の URL ベースの保存先は、Windows のローカルファイルシステムと同じ前提では扱えません。ローカルパス、同期済みパス、Web URL、API 経由アクセスを区別してください。

特に次の前提を置いた処理は、保存先変更時に失敗しやすいため重点確認します。

- カレントディレクトリが存在する
- 相対パスで常に同じファイルを参照できる
- URL を `Open`、`Dir`、`FileSystemObject` 等へ直接渡せる
- ファイルサイズ、更新日時、属性をローカルファイルと同様に取得できる
- ファイルを排他制御なしで上書きできる

#### 推奨改修

1. パスをコードから分離し、設定シート、設定ファイル、名前定義等で管理する
2. パス結合処理を共通関数化する
3. ローカルファイル操作とクラウドストレージ操作を分離する
4. 一時ファイルを使う場合は、作成、競合回避、削除、例外時の後処理を実装する
5. 読取専用、権限不足、ファイル不在、ロック中を明示的に処理する

---

### 3.2 Win32 API、Windows Shell、外部ライブラリ

#### 主な検索キーワード

- `Declare`
- `Lib`
- `PtrSafe`
- `LongPtr`
- `GetWindow`
- `Sleep`
- `SendMessage`
- `GetUserName`
- `CreateObject("WScript.Shell")`
- `CreateObject("Shell.Application")`
- `Shell`
- `WshShell`

#### 参照設定の確認対象例

- Microsoft Shell Controls And Automation
- Windows Script Host Object Model
- その他、対象環境に標準搭載されない COM ライブラリ

#### 判定観点

- 64 bit Office で宣言が成立するか
- `Long` とポインターサイズの扱いが正しいか
- エンドポイント保護機能や実行制御の対象にならないか
- 同等機能を Office 標準機能で実現できるか
- 外部プロセス起動や OS 操作が業務要件上、本当に必要か

#### 推奨方針

優先順位は次のとおりです。

1. 不要な OS 依存処理を廃止する
2. Office / VBA 標準機能へ置換する
3. 署名済み・管理可能な共通コンポーネントへ集約する
4. API 継続利用が不可避な場合に限り、32 bit / 64 bit 両対応と安全性を精査する

#### 置換例: 待機処理

API の `Sleep` を単純に削除すると、処理順序や外部処理完了待ちが崩れる可能性があります。固定時間待機が要件に合う場合は、Office の待機機能を候補にできます。

```vb
Application.Wait Now + TimeSerial(hours, minutes, seconds)
```

ただし、画面応答性、時刻跨ぎ、外部処理の完了保証などを確認し、可能であれば「一定時間待つ」方式ではなく「完了条件を確認する」方式を優先します。

### 3.3 Power Query

#### 使用有無の判定

1. Excel の［データ］を開く
2. ［クエリと接続］を開く
3. クエリが存在するか確認する
4. 各クエリのデータソース、パラメーター、資格情報、プライバシーレベルを確認する

#### 保存先変更時の ToDo

- [ ] 接続先を新しいデータソースへ変更する
- [ ] SharePoint を利用する場合、原則としてサイトのルート URL と対象ファイルの絞込み条件を分ける
- [ ] ファイル名だけでなく、フォルダーパス、拡張子、更新日時等の絞込み条件を確認する
- [ ] 列名、型、シート名、テーブル名の変更耐性を確認する
- [ ] 認証方式と資格情報の保存範囲を確認する
- [ ] 自動更新、手動更新、バックグラウンド更新の挙動を確認する
- [ ] 複数ファイル結合時のスキーマ差分を確認する
- [ ] エラー行、空ファイル、一時ファイルを除外する

#### 留意点

- サンプルファイルに依存した変換は、列追加や名称変更で失敗する場合があります
- 個人の資格情報や個人専用 URL を埋め込まないでください
- 接続先 URL、サイト名、フォルダー名は外部共有資料へ記載せず、プレースホルダーで示してください

### 3.4 バーコード生成

#### 改修対象の判定

- 特定のバーコードフォントに依存している
- セルにアスタリスク等を付加した文字列を表示している
- ActiveX のバーコードコントロールを利用している
- 対象環境に必要なフォントまたはコントロールが存在しない

#### 方式選定

次の観点で方式を比較します。

1. 対象端末への追加インストール要否
2. ActiveX 依存の有無
3. 32 bit / 64 bit 対応
4. バーコード規格への適合
5. 印刷品質、縮尺、余白、解像度
6. 読取機器との互換性
7. 配布、保守、ライセンス条件

#### 留意点

- Code 39 と Code 128 は異なる規格です。既存の文字列を別規格へ変更する場合は、読取側システムとの互換性を確認してください
- コントロールの `Style` 値は製品やバージョンに依存する可能性があるため、仕様書と実機で確認してください
- 見た目がバーコードになっているだけでは合格とせず、実際のスキャナーで読取テストを行ってください
- ActiveX を有効化することだけを前提とした解決は避け、安全性と配布性を含めて代替方式を検討してください

---

### 3.5 マクロ、ActiveX、信頼設定

#### 確認事項

- ファイルの入手元と信頼性
- デジタル署名の有無と有効性
- 信頼できる場所の設定範囲
- ActiveX コントロールの種類と必要性
- マクロ実行ポリシー
- 保護ビュー、ブロック、ダウンロード由来属性の影響

#### セキュリティ上の留意点

マクロや ActiveX の制限を一律に緩和する手順は、外部共有用の標準手順には含めません。解除が必要な場合は、組織のセキュリティポリシーに従い、対象ファイルの出所、署名、保管場所、影響範囲を確認した上で、必要最小限の設定にしてください。

推奨順位は次のとおりです。

1. 信頼できる発行元によるコード署名
2. 管理された配布場所の利用
3. 対象を限定した信頼設定
4. ActiveX や未署名マクロへの依存削減

## 4. 標準改修手順

### Step 1. 現状把握

1. 対象ファイルと関連ファイルを収集する
2. 現行環境と移行先環境の差分を整理する
3. VBA プロジェクト内の全モジュールを確認する
4. 標準モジュールだけでなく、シート、ThisWorkbook、フォーム、クラスも確認する
5. 外部リンク、参照設定、クエリ、名前定義、ActiveX、アドインを棚卸しする

### Step 2. 静的検索

VBE の検索範囲を「カレント プロジェクト」に設定し、以下を検索します。

- パス: `\\`、`:\`、`.Path`、`.FullName`
- ファイル操作: `Dir`、`Open`、`Kill`、`FileCopy`、`FileSystemObject`
- API: `Declare`、`Lib`、`PtrSafe`
- Shell: `Shell`、`WScript.Shell`、`Shell.Application`
- DB 接続: `ConnectionString`、`Provider=`、`OLEDB`、`ODBC`
- 外部実行: `.Run`、`.Exec`

検索結果は、該当モジュール、プロシージャ、行、用途、改修要否で一覧化します。

### Step 3. 影響分析

各該当箇所について、次を確認します。

- どの入力を受けるか
- どのファイル、DB、外部機能に依存するか
- どのプロシージャから呼ばれるか
- 失敗時にどの状態が残るか
- 代替機能へ変更した場合の業務影響は何か

### Step 4. 改修

- 変更は可能な限り小さくしつつ、設定分離と共通化で再発を防ぐ
- 不要な宣言、参照設定、処理を削除する
- エラーを握りつぶさず、利用者が原因を特定できるメッセージまたはログを残す
- 認証情報、個人情報、内部 URL をコードやログへ出力しない

### Step 5. テスト

修正箇所だけでなく、対象プロシージャ全体、その呼出元、関連する入出力まで確認します。テスト証跡には、入力条件、期待結果、実結果、判定、実施環境を記録します。

### Step 6. レビューと引渡し

- コードレビュー
- セキュリティレビュー
- テスト結果レビュー
- 変更一覧と既知制約の確認
- バックアップからの復旧確認

## 5. テスト観点

### 5.1 機能テスト

- ファイル選択、読込、作成、更新、保存、印刷、出力
- DB 接続、検索、登録、更新、削除、トランザクション
- Power Query の更新と出力テーブル
- バーコードの生成、印刷、実機読取
- ボタン、フォーム、イベント、ショートカット

### 5.2 異常系テスト

- ファイルが存在しない
- フォルダーが存在しない
- 権限がない
- ファイルがロックされている
- ネットワークが切断される
- DB 接続がタイムアウトする
- データ形式が不正、空、上限超過
- クエリの列、シート、テーブルが変更される
- ActiveX または参照ライブラリが存在しない

### 5.3 非機能テスト

- 処理時間
- 大容量データ時のメモリ使用量
- 同時実行と競合
- 端末差、Office の bit 数差、バージョン差
- 再実行可能性
- ログの十分性と機密情報の非出力

### 5.4 回帰テスト

- 改修前後の出力差分
- 数式、書式、名前定義、ピボット、グラフへの副作用
- Access のフォーム、レポート、クエリへの副作用
- 既存の利用手順が維持されているか

- 月末まで等の作業期限

### 8.3 内部環境・構成情報

- 内部端末、既存ネットワーク、移行先環境の固有名称

### 8.5 技術的に断定を避けた情報

- 特定環境では必ず動作しない、という環境固有の断定
- 特定のエラーだけから Win32 API 利用を断定する記述
