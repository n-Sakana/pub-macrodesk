# 実画面の証拠 — 2026-08-06 の設計整理

先生の実機確認（2026-08-05）で挙がった 7 点を直したあと、**実 WebView2 の
MacroStudio を端から端まで歩かせて撮った**画面です。DOM の数え上げでは見えない
もの（重なり・見切れ・行間・面積配分・任意入力が使えるように見えるか）を、
人が目で確かめるための材料です。

## 撮り方

```powershell
$env:MACROSTUDIO_SMOKE_SHOTS = '<出力先フォルダ>'
$env:MACROSTUDIO_SMOKE_WINDOW = '4x3'
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File tests\test-flow-webview.ps1 -BookPath testdata\input_win32_sleep.xlsm
```

`MACROSTUDIO_SMOKE_SHOTS` を置かなければ 1 枚も撮りません。通常の
`test-flow-webview.ps1` の挙動は変わっていません。撮影点は
`tests\P10FlowSmoke.cs` の `Shot()` / `ShotAt()` 呼び出しです。

試料は `testdata\input_win32_sleep.xlsm`（`sample-book\sample_win32_sleep.xlsm`
の複製。先生が実機確認に使ったものと同じ SHA-256）。ウィンドウは製品が実際に
開く 1120×840 です。

## 何を見るか

| ファイル | 画面 | 直したところ |
|---|---|---|
| `01-diagnose-request.png` | 2 `diagnose` AIへ診断を依頼 | 「仕様書・手順書…」の一回限りの強調をやめ、標準の補足 1 行へ。ボタンとの重なりが無いこと。「気になっていることを書き足す」が **開いた任意入力**で、枠も文字も通常であること |
| `02-verdict.png` | 3 `findings` 診断結果 | A〜D の 4 枚のカードを廃し、**総合判定 1 つ**。この試料は B なので赤い D はどこにも出ない。判定の意味・根拠・「判定は 1 つだけ」の説明が字の大きさの順に並ぶ |
| `03-nextstep-and-scope.png` | 4 `nextStep` 改修の選択 | 上部。分類見出しごとの操作カード（先生の評価が良い部分。崩していない） |
| `03b-change-scope.png` | 同上・下部 | **変更範囲が 1 つの二状態スイッチ**。「いま有効」「切り替える」が文字で出て、それぞれ何を許すかも文字で出る。詳細オプションの二重表現は無い |
| `04-repair-input.png` | 5 `repairInput` 直す指摘 | 「追加の要望を書く［任意］」が開いた任意入力。下のチェック行との間が詰まっていないこと |
| `05-repair-request.png` | 6 `repair` AIへ改修を依頼 | 2-1-1 と同じ標準表現に統一されていること |
| `06-refused-intake.png` | 同上・取り込み失敗 | 標準の警告コンポーネント。アイコン＋見出し＋本文＋手順＋検査番号。色だけに意味を持たせていない |

`01` と `04` の中央下に出ている緑の枠はトースト（数秒で消える重ね表示）で、
画面の要素ではありません。

## 目視で確かめたこと

- 文字とボタンの重なり — 無し（2-1-1 / 3-4-5 の強調表示を撤去した箇所を含む）
- 見切れ — 無し。変更範囲は折り返し位置より下にあるので `03b` で送って撮影
- 不自然な空白 — 任意入力とその下のチェック行の間を `--space-4` へ（`.field + *`）
- 行間・フォント階層 — 見出し 17px / 本文 14px / 補足 12px の 3 段。判定の
  1 文字だけが 46px（`--type-display-size`）
- 任意入力が disabled に見えないこと — `01` `04`。枠・背景・文字色は通常のまま、
  「任意」はタグの文字で示す
- トグル状態が明瞭なこと — `03b`。チェック＋「いま有効」＋色の 3 重
