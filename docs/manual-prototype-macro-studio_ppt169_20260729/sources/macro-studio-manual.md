本書のもとになった事実は、すべて `C:\repos\pub\pub-macrodesk` の実装（`assets/js/screens.js`,

## 0. 本書の位置づけ

- 対象読者: VBA や開発に詳しくない業務担当者。Excel のマクロを「直したい」が、VBE を開いた
  ことはない人。
- 目的: ブックの取り込みから、AI への改修依頼、AI 返答の取り込みと差分確認、改修済みブックの
  ビルド・出力まで、画面を見ながら迷わず 1 周できること。
- 書かないこと: 開発経緯、内部実装（OLE2 / MS-OVBA / WebView2 など）、設計判断の理由。
- 製品名: 本書では **Macro Studio（仮称）** と表記する。アプリ本体は UI デザイン開発中で、
  画面上のロゴ・タイトルは現時点で **MacroDesk** のまま。掲載する画面写真にもそのまま写る。
  本書ではこの点を明示し、名称が未確定であることを読者に伝える。
- 本書は**初回試作**。画面写真はアプリ同梱のデモ用データ（`?demo=1`）を実際に描画して撮影した
  ものであり、UI そのものは現行実装だが、写っているブック名・モジュール名・行数・日時は
  デモ用の値である。

## 1. Macro Studio でできること（全体像）

このツールは **VBE（Visual Basic Editor）を一度も開かずに**、Excel マクロ（VBA）の改修を
GUI だけで完結させる。

役割分担が最大の特徴:

- **判断するのは AI チャット**（例: Microsoft 365 Copilot Chat）。どこを直すか、どう直すかは
  すべて AI が決める。
- **Macro Studio は判断しない。** 判断材料（マクロのコード全文）を運び、AI の返答を安全に
  ブックへ書き戻す配管に徹する。
- ツール自体は**完全ローカル動作**。AI との通信はブラウザのチャット AI 側で行う。ツールが
  ネットワークへ出ることはない。

画面は 4 つの手順に分かれ、その中がさらに小さな画面に分かれる（全 12 画面）。
画面上部に常に「1 ブックを読み込む / 2 AIへ依頼する / 3 返答を取り込む / 4 ブックを作る」の
進捗が出る。1 画面につき決めることは 1 つ。右下の **［次へ］** は、その画面ですべきことが
終わるまで押せない（押せるようになったことが合図になる）。

| 手順 | 画面数 | 画面上の表示 | ここで決めること |
|---|---|---|---|
| 手順 1 | 2 | ブックを読み込む | どのブックを改修するか |
| 手順 2 | 4 | AIへ依頼する | AI に何を依頼するか |
| 手順 3 | 3 | 返答を取り込む | AI の変更を採用するか |
| 手順 4 | 3 | ブックを作る | 出力名を確認してビルド |

**元のブックは、最初から最後まで一切変更されない。** 出力は必ず別ファイル。

## 2. はじめる前に

準備するもの:

- 改修したい Excel ブック（`.xlsm` / `.xlam` / `.xlsb` / `.xls`）。
  形式の判定は拡張子ではなくファイルの中身で行うため、拡張子が違っても中に VBA があれば
  読み込める。
- チャット AI が使えるブラウザ（Microsoft 365 Copilot Chat など）。
  ファイル添付ができるものを使う。

動作要件:

| 項目 | 要件 |
|---|---|
| OS | Windows 10 / 11 |
| インストール | 不要。フォルダをコピーするだけ |
| Excel | ツール自体には不要（改修後の動作確認時のみ使用） |
| ネットワーク | ツールは完全ローカル動作 |

起動: **`launch.vbs` をダブルクリック**。黒い画面（コンソール）は出ない。
画面右上の月／太陽ボタンでライトとダークを切り替えられ、選択は次回起動時も維持される。

## 3. 手順 1: ブックを読み込む（2 画面）

### 画面 1-1「改修するExcelブックを読み込みます」

やること: 改修したいブックをドロップするか、クリックして選ぶ。

- 画面中央の点線の枠へ Excel ブックをドラッグ＆ドロップする。
- またはその枠をクリックしてファイル選択ダイアログから選ぶ。
- Excel で開いたままのブックもそのまま添付できる。
- 画面には「元のブックには書き込みません。」と出る。実際に読み取るのはマクロのコードだけ。

読み込みに成功すると、枠がファイル名とパスの表示に変わり、**［選び直す］** が出る。
右下の［次へ］が押せるようになる。

### 画面 1-2「読み込んだマクロを確認します」

やること: 読み込んだ内容が意図どおりか確認する。

画面に出る 4 つの数値:

- ファイル名とパス
- **モジュール** … 読み込んだモジュールの数
- **合計行数** … 全モジュールの合計行数
- **読み取り警告** … 「あり」なら一部に不整合。読み取れる範囲で処理は続く

その下にモジュール名が並ぶ（マウスを乗せると行数が出る）。
違うブックだった場合は **［別のブックを選ぶ］**。合っていれば［次へ］。

## 4. 手順 2: AIへ依頼する（4 画面）

### 画面 2-1「AIチャットへ渡す改修依頼を作ります」

やること: 依頼文の作り方を 2 つから選ぶ。

- **用意された改修依頼を選ぶ** … 目的に近いひな形を選び、必要な部分だけ直す。
- **改修してほしい内容を自分で書く** … 何をどう直すか、最初から入力する。

どちらかを選ぶと［次へ］が押せる。「自分で書く」を選んだ場合は画面 2-2 を飛ばして
画面 2-3 へ進む。

### 画面 2-2「目的に近い改修依頼を選びます」（ひな形を選んだ場合のみ）

やること: ひな形を 1 つ選ぶ。

- ひな形の一覧が出る。各項目にはひな形の名前と、改修指示の 1 行目が要約として出る。
- ひな形は `presets\` フォルダに置いた Markdown ファイルから自動で作られる。
  ボタン名はファイル名ではなく、ファイル内の見出し（`# ...`）。
- 現在同梱されているひな形は **「新端末移行（Win32 API 依存の解消）」** の 1 つ
  （`presets\サンプル_新端末移行.md`）。
- 書式が足りないファイルは選べず、画面下部に「読み込めないひな形」としてファイル名と理由が
  出る。直せばそのまま使える。
- ひな形の追加・削除・名前変更は、この画面を開き直せば反映される。

補足（管理者向け・利用者は読み飛ばしてよい）: ひな形は 1 ファイル 1 依頼。`# 名前`、
`## 改修指示`、`## 出力指示` の 3 つが必要。`<!-- ... -->` のコメントは AI へ渡らない。

### 画面 2-3「AIへ伝える改修内容を確認します」

やること: 依頼文を読み、必要なら書き足す。

- ひな形を選んだ場合、その「改修指示」が入力欄に入った状態で表示される。
- そのまま使ってもよいし、自分の言葉で足しても消してもよい。
- 入力欄の下に **出力指示**（AI に返答のしかたを指示する文面）が折りたたまれて出る。
  クリックすると中身を読める。この文面は依頼文の末尾に自動で付いて送られる。
- 「自分で書く」を選んだ場合、出力指示は付かない（「出力指示はまだありません」と出る）。

### 画面 2-4「AIチャットへ改修を依頼します」

やること: 2 つのカードを上から順に片付ける。両方終わると［次へ］が押せる。

1. **依頼文をチャットへ貼り付ける** — ［依頼文をコピー］を押すと、AI への依頼文が
   クリップボードへコピーされる。**コード本文はコピーされない。**
2. **コード全文ファイルを添付する** — ［ファイルの場所を開く］を押すと、エクスプローラーが
   `source-code.md` を選択した状態で開く。このファイルをチャットへ添付する。

画面下部に、この改修専用の出力フォルダのパスと、その中にできるファイル
（`request.md`, `source-code.md`）が並ぶ。

出力フォルダの場所は
`<元ブックのフォルダ>\MacroDesk\<ブック名>_<日時>\`（例: `受注管理_20260729_101500`）。

**コードと依頼を分けて渡すのが要点。** 添付ファイル内で指示文とコードが混ざると、チャット AI が
コードを「全文を取得できない」と誤認する実測があったため、コードは添付ファイル、依頼文は
チャット本文、と分けている。

## 5. AIチャット側での操作（ツールの外）

Macro Studio はここには関与しない。ブラウザのチャット AI で次を行う。

1. チャットの入力欄に **依頼文を貼り付ける**（Ctrl+V）。
2. 同じメッセージに **`source-code.md` を添付する**。
3. 送信して、返答を待つ。

同梱ひな形の出力指示を使った場合、AI は次の形式で返す:

- 冒頭に **「■ 改修サマリー」** … どのモジュールをどう変えたかの箇条書き。
  これが、このあとの取り込み作業の指示書を兼ねる。**まずここを読む。**
- 続けて、改修したモジュールごとに **「■ モジュール名」** の見出し + 改修後コード全文の
  コードブロック。
- 新しい標準モジュールは **「■ <名前>（新規）」** の見出しで返る。
- 変更していないモジュールは返らない。

うまくいかないときは、画面 2-3 へ戻って依頼を言い直せる。

## 6. 手順 3: 返答を取り込む（3 画面）

左側に**モジュール一覧**が常に出る。これがそのままモジュールツリーで、モジュールを選ぶ場所は
ここだけ。各行の色と状態表示:

| 状態表示 | 意味 |
|---|---|
| 未取り込み | まだ何もしていない |
| 次 | いま選んでいる（未取り込み） |
| 取込済み / 確認中 | コードを貼ったが、採用/不採用を決めていない |
| 採用済み（緑） | 採用した。ビルドで書き戻される |
| 変更なし | 貼ったが元と同じだった |
| 対象外 | 対象から外した |

画面には「青色は、いま確認しているもの／緑色は、採用済みのもの」と凡例が出る。

### 画面 3-1「AIの返答から、取り込むモジュールを選びます」

やること: モジュールを 1 つ選び、そのコードを取り込む。

1. AI の返答の「■ 改修サマリー」で、変更されたモジュール名を確認する。
2. 左の一覧からそのモジュールを選ぶ。
3. AI の返答のコードブロックを、先頭から末尾まで全文コピーする
   （コードブロックのコピーボタンを使うのが確実）。
4. **［クリップボードから取り込む］** を押す。**Ctrl+V でも貼れる。**

画面には取り込みの手順が 1・2・3 の順で常に出ている
（「AIの返答でモジュール名を探す」→「コードブロックを全文コピーする」→「この画面へ取り込む」）。

取り込むと表示が「◯◯ のコードを取り込みました」に変わり、［次へ］で差分確認へ進む。

貼り付けたテキストは自動で整えられる: 行頭の ``` のコードフェンス行は取り除かれ、
先頭の `Attribute VB_` 行群も取り除かれる（VBE でも見えない行のため）。

### 画面 3-2「AIの変更を、元のコードと見比べます」

やること: 赤（削除）と緑（追加）の行を確認し、**採用するかしないかを決める。**

- 画面は GitHub と同じ**インライン差分**。左に行番号 2 列（前・後）、削除行は赤、追加行は緑。
- 上部のツールバー:
  - **変更 n 行** … 変更行数
  - **［↑ 前の変更］［↓ 次の変更］** と `1/n` … 変更箇所を順に送る
  - **［変更箇所のみ］** … 変更のない行を隠す（200 行超のモジュールは既定でオン）
  - **［折り返し］** … 長い行を折り返す
  - **［手動修正］** … その場でコードを直す（後述）
  - **［貼り直す］／［貼り付けを取り消す］**
- 下部で決める:
  - **［この変更を採用する］** … ビルドで書き戻す対象になる
  - **［この変更を使わない］** … 取り込みを取り消す

**［採用する］を押して初めてビルド対象になる。** 貼っただけでは書き戻されない。

採用すると左の一覧が緑の「採用済み」になり、［次へ］が押せる。
未処理のモジュールが残っていれば画面 3-1 へ戻り、同じ操作を繰り返す。

#### ［手動修正］— 軽微な写し間違いをその場で直す

コードフェンスが混ざった、行が欠けた、など軽微な写し間違いは、AI へ戻らずここで直せる。

1. ［手動修正］を押す。右側が編集欄になる。
2. 直して **［修正を反映］**。差分を見直せる。
3. 未反映のまま画面を離れようとすると「未反映の修正を破棄しますか？」と確認が出る。

#### AI が新しいモジュールを追加した場合

1. 左の一覧の下にある **［AIが追加したモジュール］** を押す（画面 3-1 でのみ押せる）。
2. AI の返答のコードブロックをコピーしておく。
3. **モジュール名**を入力して **［新規モジュールとして取り込む］**。

追加できるのは**標準モジュールのみ**。モジュールの削除・名前変更はできない。

### 画面 3-3「採用した変更を確認します」

やること: 書き戻す対象がこれで合っているか確認する。

集計が 4 つ出る: **書き戻し / 変更なし / 未処理 / 追加・削除（行数）**。
その下に採用済みモジュールの一覧。

まだ取り込むものがあれば **［別のモジュールを取り込む］** で画面 3-1 へ戻れる。
1 件以上採用していれば［次へ］が押せる。

## 7. 手順 4: ブックを作る（3 画面）

### 画面 4-1「作成する改修済みブックを確認します」

やること: 出力ファイル名を確認する。

- 既定の名前は `<元のブック名>_macrodesk<元の拡張子>`（例: `受注管理_macrodesk.xlsm`）。
- 変更してよいが、**拡張子は元のまま**にする。`\ / : * ? " < > |` は使えない。120 文字まで。
- 画面下部に、この改修専用の出力フォルダと、その中にできる 4 つのファイルが並ぶ。
- ［次へ］を押すとビルドが始まる。

### 画面 4-2「改修済みブックをビルドしています」

やること: 待つ（通常 1〜2 秒）。

書き戻したあと、ツールが自動でブックを読み直し、モジュール名とコードが意図どおり
書き込まれたかを検証する。

### 画面 4-3「改修済みブックを作成しました」

出力フォルダのパスと、**［出力フォルダをエクスプローラーで開く］** が出る。
できたファイルは 4 つ:

| 表示 | ファイル名 | 中身 |
|---|---|---|
| AIへ渡した依頼文 | `request.md` | 実際に AI へ渡した依頼文 |
| 元マクロのコード全文 | `source-code.md` | 添付した VBA コード全文 |
| 改修済みブック | 画面 4-1 で決めた名前 | 書き戻し済みの新しいブック |
| 変更内容の確認レポート | `diff-report.html` | 全モジュールの改修前後を 1 ファイルで確認 |

`diff-report.html` はブラウザで開ける自己完結の HTML。左にモジュールツリー、右に画面と同じ
インライン差分が出る。あとから見返す・共有するのに使える。

**最後に Excel で開いてマクロの動作を確認する。** ここまでで元のブックは一切変更されていない。

失敗した場合は「ビルドできませんでした」と出て、モジュール別の結果表が出る。
出力ファイルは残さない。元のブックは変更されていないので、**［もう一度ビルドする］** で
何度でもやり直せる。

## 8. 困ったとき

| 症状 | 見るところ |
|---|---|
| 起動しない / 白い画面のまま | WebView2 ランタイム未導入の可能性。起動時のエラー案内に従う |
| 「マクロが見つかりません」 | そのブックにマクロ（VBAプロジェクト）が入っていない |
| ブックを添付できない | 対象ブックを Excel で開いたままにしていないか確認する |
| ひな形のボタンが出ない | 画面 2-2 の「読み込めないひな形」に理由が出る。`# 名前` `## 改修指示` `## 出力指示` が揃っているか、UTF-8 保存かを確認 |
| 依頼テンプレートを読み込めない | `templates\request-template.txt` が UTF-8 で保存され、`{{REQUEST_TEXT}}` を含むか確認 |
| AI の返答が思っていたものと違う | 画面 2-3 へ戻って依頼を言い直す |
| 貼り付けたコードに余計な行が混ざった | 画面 3-2 の［手動修正］でその場で直す |
| ビルドに失敗した | 画面の指示に従う。元のファイルは無傷なので何度でもやり直せる |

ログ: `%LOCALAPPDATA%\MacroDesk\logs\` に動作ログが残る。問い合わせ時に添付する。
起動そのものに失敗した場合も、その理由がこのログに記録される。

## 9. このツールがやらないこと

- 改修対象の検出・提案（判断はすべてチャット AI 側）
- チャット AI の返答の自動解釈（人が読んで、人が選んで貼る）
- モジュールの削除・名前変更、標準モジュール以外の新規追加
- 元ファイルの上書き（出力は常に別ファイル）

## 10. 用語

| 画面の言葉 | 意味 |
|---|---|
| モジュール | マクロのコードが入っている入れ物。1 ファイルのようなもの |
| 標準モジュール | 一般的な処理を書くモジュール。新規追加できるのはこれだけ |
| ドキュメントモジュール | シートやブックに紐づくモジュール |
| クラス／フォームモジュール | それぞれ独自の役割を持つモジュール |
| 差分（diff） | 元のコードと新しいコードの違い。赤が削除、緑が追加 |
| ビルド | 採用した変更を書き戻して、新しいブックを作ること |
| ひな形（プリセット） | よく使う改修依頼の定型文 |

## 11. 試作版で仮置きにした箇所（開発中のため）

本書は初回試作であり、次の点は現時点で未確定・仮置きである。

1. **製品名** — 本書は「Macro Studio（仮称）」。アプリ画面・ロゴ・ログの保存先は現時点で
   `MacroDesk` のまま。改名時に本書の画面写真も差し替えが必要。
2. **画面写真** — アプリ同梱のデモ用データ（`?demo=1`）を実際に描画して撮影した現行 UI。
   ブック名「受注管理.xlsm」、モジュール名、行数、日時はデモ用の値であり実在の業務データでは
   ない。UI デザインは開発中のため、細部は変わりうる。
3. **AI チャット側の画面** — Copilot Chat 等の外部サービス画面は本書に載せていない。
